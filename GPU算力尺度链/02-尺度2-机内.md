# 尺度 2 · 机内（2–8 卡）

## 0. 本篇对象

> **原样题面**：按照这种从小到大的尺度，给我每个尺度详细介绍一下。我的中心是学习。你要给我介绍学习的重点。比如学传统网络的最大重心就是 IP 和路由，像这种形式，你在每个层级章节把重心罗列并且详细讲解。

**本篇讲尺度链第 2 格：一台机器里的多张 GPU。** 主角是 PCIe/NVLink 互联和 NCCL。物理范围从单卡插槽向外，到一台服务器机箱边界为止。

---

## 1. 学习重心（先罗列）

对标"学传统网络 = 学 IP + 学路由"：

```text
学机内 = 学「拓扑」 + 学「集合通信」

重心一：拓扑 —— 卡和卡怎么连的，谁离谁近，带宽差多少
重心二：集合通信 —— AllReduce 怎么算，为什么算法要跟着拓扑走

其余都是配角：
  NCCL 的 API      —— 只是调用入口，几个函数
  GPUDirect        —— 只是让数据绕过 CPU 的优化手段
  PCIe / NVLink 规格 —— 只是拓扑的具体参数
```

**为什么是这两个**：因为机内的全部复杂性，都来自"卡之间不是平等的全连接"。拓扑决定了性能上限，集合通信算法决定了你能不能摸到这个上限。学传统网络先学"网络长什么样、包怎么选路"——机内对应的就是"卡怎么连、数据怎么交换"。

---

## 2. 重心一详解：拓扑

### 2.1 核心直觉：八张卡不是八张平等的卡

一台 8 卡机里，GPU 之间的连接速度差异可以是几倍。有的卡挨着交换机，有的隔着两跳；有的走 NVLink 直连带宽极高，有的得绕 PCIe。

```text
NVLink 直连      —— 卡与卡之间专用高速通道，带宽最高
NVLink Switch    —— 通过交换芯片，8 卡全互联，任意两卡等距
PCIe Switch      —— 走 PCIe 交换，带宽低一些，且可能要经过 CPU 根复合体
```

**关键转变**：从"我有 8 张卡"变成"我有一张**有形状的**卡间网络"。形状决定了数据怎么走最快。

### 2.2 常见拓扑形态

```text
是一条链？   0—1—2—3     相邻快，两端远
是一个环？   环形传递      每步等距，但跳数多
是一颗星？   全经过中心    中心是瓶颈
是全互联？   任意两卡直连   最理想，成本最高
```

现代高端机（如 DGX/HGX）走的是 **NVLink Switch 全互联**：8 张卡两两之间带宽一样。中低端机器多是 PCIe 树形，卡间要绕，性能不均匀。

### 2.3 学到什么程度算掌握

```text
能回答：为什么同一台机器上，不同 GPU 对之间通信延迟不同
能回答：怎么查这台机器的拓扑（nvidia-smi topo -m）
能判断：一个 AllReduce 在这台机器上会走哪条路径、瓶颈在哪
能理解：为什么买机器时"卡间互联拓扑"和"卡本身"同样重要
```

## 3. 重心二详解：集合通信

### 3.1 核心直觉：训练不是"发消息"，是"全体同步"

普通网络是点对点：A 发一个包给 B。
训练里的通信是**全体动作**：所有卡各算一份梯度，要"合起来再分发回每个人"。这就是集合通信（collective）。

```text
AllReduce     —— 每卡有一份数据，求和后每卡都拿到结果   ← 训练最常用
Broadcast     —— 一张卡的数据发给所有人
AllGather     —— 每人一小块，最后每人拿到完整拼接
ReduceScatter —— 求和后把结果切片分给每人
```

AllReduce 是绝对重心——**数据并行的梯度同步就是它**。

### 3.2 AllReduce 怎么算：算法跟着拓扑走

这是本篇最值得花时间的地方。同样一个"求和分发"，算法不同，性能差几倍。

```text
【Ring AllReduce】—— 环形
  每卡只和左右邻居通信，数据绕圈传递
  优点：带宽最优，每卡收发量恒定，不随卡数增长
  缺点：跳数多，延迟随卡数增长
  适合：大数据量（梯度通常很大）

【Tree AllReduce】—— 树形
  按树结构层层汇聚再散开
  优点：延迟低，跳数少（log N）
  缺点：根节点压力大
  适合：小数据量

【Double Binary Tree】—— NCCL 实际用的
  两棵错位的树，规避单根瓶颈，兼顾延迟和带宽
```

**关键洞察**：为什么算法必须跟着拓扑走？因为 ring 要求邻居之间带宽高，tree 要求树的层级和物理距离匹配。算法跑在错误的拓扑上，等于让数据绕远路——NCCL 的核心价值就是**自动探测拓扑，然后选对算法**。

### 3.3 通信与计算重叠

```text
朴素做法：算完 → 同步通信 → 再算下一轮   （通信时 GPU 空等）
优化做法：一边算后面的层，一边同步前面的梯度  （通信被计算掩盖）
```

这是机内的进阶主题，但根子还在"拓扑 + 算法"——你得知道通信要花多久，才能安排计算和它重叠。

### 3.4 学到什么程度算掌握

```text
能回答：AllReduce 和 AllGather 的区别，各自在什么场景用
能手推：ring AllReduce 为什么每卡收发量是 2(N-1)/N × 数据量
能解释：为什么大数据量用 ring、小数据量用 tree
能理解：NCCL 为什么要做拓扑探测——算法选择依赖它
```

## 4. 八问展开

```text
【是什么】
  一台机器内多张 GPU 的互联与协同。软件主角是 NCCL。

【物理边界】
  管：一台服务器机箱内，卡与卡之间的数据交换
  不管：机器与机器之间（那是尺度 3）

【跨哪道鸿沟】
  单卡算力 ↔ 多卡合力。没有这一格，8 张卡就是 8 台孤岛。

【内部构成】
  硬件：PCIe / NVLink / NVLink Switch / GPUDirect
  软件：NCCL（集合通信库）+ CUDA 的流与同步机制

【对上给什么 / 对下藏什么】
  对上给：AllReduce 等原语 —— 一行调用完成全体同步
  对下藏：环形还是树形、走 NVLink 还是 PCIe、怎么切片怎么流水线

【概念归位】
  PCIe / NVLink = 拓扑（物理连接）
  NCCL          = 通信原语 + 拓扑感知算法
  GPUDirect     = 优化手段（绕过 CPU 中转）

【现在咋样 + 怎么用】
  用法：PyTorch 的 DistributedDataParallel 默认后端就是 NCCL
  典型场景：单机 8 卡数据并行，梯度同步靠 AllReduce

【为什么不能省 + 交接点】
  没有这一格：多卡训练退化成单卡，卡数加了性能不涨
  交接点：网卡（IB / RoCE）—— 一台机器装不下的通信，交给尺度 3
```

## 5. 本篇小结

```text
一句话记住：机内 = 拓扑 + 集合通信

拓扑回答"卡怎么连"：NVLink / PCIe / Switch，形状决定上限
集合通信回答"数据怎么换"：AllReduce 为主，ring vs tree 跟着拓扑选

最容易踩的坑：以为 8 张卡天然快 8 倍，忽略拓扑和同步开销
最该建立的直觉：NCCL = 拓扑探测 + 算法选择，它不是简单的消息库
```
