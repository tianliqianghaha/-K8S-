# 尺度 3 · 集群内（AI Fabric）

## 0. 本篇对象

> **原样题面**：按照这种从小到大的尺度，给我每个尺度详细介绍一下。我的中心是学习。你要给我介绍学习的重点。比如学传统网络的最大重心就是 IP 和路由，像这种形式，你在每个层级章节把重心罗列并且详细讲解。

**本篇讲尺度链第 3 格：一个集群内、机器与机器之间的高性能互联。** 主角是 InfiniBand / RoCEv2、交换机、无损网络。物理范围从一台服务器网卡向外，到整个 AI 集群边界为止。

这一格就是业界说的 **AI Fabric**。它是"交接处"——GPU 软件栈的外面，算力网络的里面。

---

## 1. 学习重心（先罗列）

对标"学传统网络 = 学 IP + 学路由"：

```text
学集群内 = 学「无损」 + 学「抗大象流」

重心一：无损网络 —— 为什么训练怕丢包，怎么做到几乎不丢
重心二：大象流    —— 为什么训练流量和网页流量是两种东西，怎么不让链路堵死

其余都是配角：
  IB vs RoCEv2  —— 两条实现路线，理解重心后自然分清
  交换机规格     —— 参数，不是原理
  NCCL 跨节点   —— 算法在尺度 2 已学，这里只是换了传输介质
```

**为什么是这两个**：因为集群网络和普通网络的根本差别不在于"更快"，而在于**流量性格完全不同**。普通网络跑的是海量小流、能丢包重传；训练跑的是少数超大流、同步突发、丢一个包整轮卡住。抓住了"流量性格"，这一层所有设计（无损、拥塞控制、负载均衡）就都串起来了。

---

## 2. 重心一详解：无损网络

### 2.1 核心直觉：训练为什么怕丢包

普通网页下载丢一个包，TCP 重传一下，你几乎无感。
分布式训练丢一个包：**所有 GPU 的梯度同步卡在那里等这一个包**，整轮迭代停摆。

```text
传统网络假设：丢包是常态，靠上层重传兜底
训练网络要求：近乎零丢包，因为同步是全局的，一个包拖住所有人
```

行业里有个常被引用的数字：**1% 的丢包就可能让训练吞吐下降三成以上**。这就是为什么要专门造一张"无损"的网络。

### 2.2 怎么做到无损：两条路线

```text
【InfiniBand】
  天生基于 credit 的流控：发送方要先拿到接收方的"信用额度"才发
  没有额度就不发 —— 从根本上不会把缓冲区塞爆
  是"原生无损"的设计，性能最好，生态封闭

【RoCEv2（RDMA over Converged Ethernet v2）】
  跑在以太网上，但要把以太网改造成无损：
  PFC  —— 优先级流控：某类流量要堵了，就发暂停帧让上游停一下
  ECN  —— 显式拥塞通知：在包上打标记，告诉接收方"路有点堵"
  DCQCN —— 基于 ECN 的速率控制：收到标记就降速，缓和了再升回来
  优点是能复用以太网生态、成本低；缺点是调参复杂
```

### 2.3 学到什么程度算掌握

```text
能回答：为什么训练网络要"无损"，而普通互联网不用
能解释：PFC 的暂停帧是怎么防止丢包的，它又带来什么新问题（死锁、队头阻塞）
能说清：IB 和 RoCEv2 的本质区别 —— 原生无损 vs 改造以太网
能判断：一个场景该选 IB 还是 RoCEv2（性能优先 vs 成本/生态优先）
```

## 3. 重心二详解：大象流

### 3.1 核心直觉：训练的流量和网页的流量不是一回事

```text
网页流量：海量小流，随机到达，此起彼伏 —— "蚂蚁流"
训练流量：少数超大流，持续占满带宽，且全体同时开始 —— "大象流"
```

大象流带来两个普通网络没遇到过的问题：

```text
问题一：hash 碰撞
  传统多路径转发（ECMP）按流做 hash，把不同流分到不同路径
  但大象流就那么几条，hash 一旦撞车，几条大象流挤到同一条链路
  结果：一条链路爆满，其他链路空闲 —— 总带宽白白浪费

问题二：同步突发（incast / burst）
  所有 GPU 在同一时刻开始同步，流量瞬间涌向交换机
  缓冲区被打满，丢包、重传、再打满 —— 恶性循环
```

### 3.2 怎么对抗大象流

```text
更细的粒度分流
  flowlet 切换：把一条大象流切成小段，按实时拥塞换路
  自适应路由：交换机根据各路径队列长度动态选路，不靠固定 hash

更大的缓冲区 + 更快的收敛
  深缓冲交换机吸收突发
  拥塞控制算法（DCQCN 等）快速降速，避免打满

拓扑设计配合
  Rail-optimized 架构：同号 GPU 跨机连同一台交换机，
  让流量模式规整，减少碰撞
```

### 3.3 学到什么程度算掌握

```text
能回答：为什么 ECMP 对大象流效果差
能解释：flowlet 和自适应路由各自怎么缓解 hash 碰撞
能理解：为什么"微秒级时延、近零丢包"是集群网络的硬指标
能说清：AI 网络优化的是"尾部延迟 P99 和连续稳定性"，不只是平均带宽
```

## 4. 八问展开

```text
【是什么】
  一个集群内、机器间的高性能互联（AI Fabric）。主角是 IB / RoCEv2。

【物理边界】
  管：一个集群内的机器间通信
  不管：集群与集群、数据中心与数据中心之间（那是尺度 4、5）

【跨哪道鸿沟】
  一台机器 ↔ 几千张卡协同。没有这一格，集群只是很多台独立的机器。

【内部构成】
  硬件：IB / RoCEv2 网卡、高基数交换机、400G/800G 光模块
  软件：NCCL 跨节点通信 + 拥塞控制 + 拓扑感知路由

【对上给什么 / 对下藏什么】
  对上给：一个"像一个整体"的集群 —— 几千卡能高效做集合通信
  对下藏：PFC/ECN/DCQCN 的调参、链路故障、拥塞控制细节

【概念归位】
  IB / RoCEv2 = 传输技术（两条实现路线）
  无损 / 大象流 = 这一层的两个根本问题（学习重心）
  AI Fabric   = 这一层的名字，指"为 AI 专门造的集群内互联"

【现在咋样 + 怎么用】
  主流：IB 性能领先，RoCEv2 因成本与以太网生态被广泛采用
  典型场景：千卡集群训练大模型，参数交换、梯度同步全靠这张网

【为什么不能省 + 交接点】
  没有这一格：卡再多也协同不起来，网络成为训练瓶颈
  交接点：DCI / 算力专线 —— 集群之外的连接，交给尺度 4
```

## 5. 本篇小结

```text
一句话记住：集群内 = 无损 + 抗大象流

无损回答"怎么不丢包"：IB 原生 credit 流控 vs RoCEv2 的 PFC/ECN/DCQCN
抗大象流回答"怎么不堵死"：细粒度分流、自适应路由、规整拓扑

最容易踩的坑：用普通以太网思路做训练网络，忽略丢包和突发
最该建立的直觉：训练流量性格和网页流量完全不同 —— 这是这一层所有设计的源头
```
