## 0. 先说这把尺子，以及它为什么必须是五条

上一轮只给了四条，是残缺的。四条只能回答「做不做得出来」，回答不了「值不值得做」。

```text
C1  一个人四周内能不能做出可对比的结果
    └─ 过不了：这是论文里的题，不是你的题。

C2  结论能不能用一张图讲清
    └─ 过不了：说明你自己也还没想清变量和指标。

C3  失败时能不能分清「想法错了」还是「实现错了」
    └─ 过不了：这题会让你在一个月后无法判断自己错在哪，
       最容易发生在「拿自己造的仿真数据训练模型」这类题上。

C4  有没有公开基线可以对照
    └─ 过不了：你的数字没人能验，等于自说自话。

C5  新颖度：公开渠道是否已经有答案
    └─ 过不了：能做出来，但做出来是复现，不是贡献。
```

三条组合规则，直接决定一个题的去留：

```text
C1–C4 全过，C5 不过  →  训练器械（用来练手，不能当选题）
C5 过，C1 不过        →  别人的题（看论文就好，别自己上）
C1–C4 全过，C5 过     →  能开工的题
任何一条 C1–C4 挂      →  直接淘汰，不讨论
```

## 2. 筛的结果

### 2.1 第一梯队：三个能开工的题

#### 第 1 名｜1.2 乱序到达 + 重排槽位有限时，选择性重传还灵不灵

```text
一句话
  └─ 你上一轮的模型假设「乱序数据可以直接放到正确位置」。
     真实的网卡只有几 MB 片上内存，槽位是有限的。
     槽位满了会怎样？这是选择性重传的下界问题。

为什么它是第一名
  ├─ 边际成本最低：你已经有事件循环、包模型和对比框架，
  │   只需加三样——乱序到达、固定槽位数、槽位耗尽即丢弃。
  └─ 它是你上一轮结论的直接延伸，不是另起一摊。

变量
  └─ 接收端槽位数（8 / 64 / 512 / 4096 / 无限）

指标
  ├─ 全员完成时刻
  ├─ 有效重传率：重传的包里真正补上洞的比例（低了说明在做无用功）
  └─ 误丢率：因槽位耗尽被丢掉的、本来没丢的包

基线
  ├─ UEC 1.1 §3.5.7.1 给了「直接放置 + 单独重传」的规范定义
  └─ Rondo 论文给了两个现成指标：OOD（乱序度）、RBO（重排缓冲占用）
     你可以直接沿用它的口径，省掉自己发明指标的风险

打分
  C1 勉强（要扩展模型，不必换工具）
  C2 过（一条「槽位 vs 完成时间」的曲线）
  C3 过（模型是自己写的，错在哪查得到）
  C4 过（UEC 条款 + Rondo 指标）
  C5 过（公开渠道还没人系统给这条下界曲线）

最大的风险
  └─ 这条曲线可能很平，槽位不敏感。那就说明瓶颈不在这——
     这本身是可写的结论，但要提前想好怎么表述。
```

#### 第 2 名｜4.1 短消息 P99 与大流吞吐的权衡曲线

```text
一句话
  └─ 让短消息优先，大流就慢；不让它优先，128 张卡一起等在屏障前。
     这条权衡曲线到底长什么样，很多集群是靠调参试出来的，没画清楚。

变量
  └─ 调度策略：先进先出 / 严格优先级 / 加权轮询 / 接收端授权

指标
  ├─ 短消息 P99 延迟
  └─ 大象流吞吐损失百分比

基线
  ├─ 前三种是交换机标准功能，行为确定
  └─ Homa 有论文与开源实现，可作参考点

打分
  C1 过  C2 过  C3 过  C4 过  C5 勉强（属定量刻画，不易出彩）

为什么排第二
  └─ 它比第一名稳，但新颖度弱，且与「协议开发」的关系稍远
     （更偏流量工程）。如果你四周内想要一份「不会失败」的产出，
     它是更安全的选择。
```

#### 第 3 名｜5.1 用公开 RDMA 监控数据集做训练阶段流量指纹

```text
一句话
  └─ 拿到一份真实的 RDMA 集群监控数据，看能不能只凭网络侧指标
     判断出「现在是训练还是推理、处在哪个阶段、有没有发生重传」。

为什么它不是主线
  └─ 它是数据分析，不是协议开发。但它零硬件、零仿真器、
     一周就能出第一张图，最适合当第 0 周的热身和并行支线。

基线
  └─ 西北工业大学公开的 DeepSeek 分布式训练/推理 RDMA 监控数据集，
     约 4000 万条 CSV 时间序列，100G RoCE + Mellanox CX6，
     1 秒采样，含队列对/完成队列/内存区计数、丢包与错误计数。

打分
  C1 过  C2 过  C3 过  C4 过（数据集本身就是基线）  C5 过

它在主线里的作用
  └─ 让你在动手改协议之前，先看一眼真实世界里「重传和拥塞」
     长什么样子。这一步能防住一个最常见的错误：
     把自己仿真出来的漂亮现象，当成真实世界的规律。
```

### 2.2 备选区：能做，但现在不建议

```text
1.3 重传超时取值对尾延迟的影响
  └─ 经典问题，公开结论多，新颖度低。可作为第 1 名的副产品顺带测。

2.1 三种哈希粒度的链路利用率分布
  └─ 教科书内容，碰撞概率可以解析算出来。
     唯一价值是练手，且它已经被解析公式锁死了上限。

3.1 拥塞信号位宽对收敛速度的影响
  └─ 题很干净，指标清楚。缺的是一条「公认基线」——
     你得自己实现对照方案，C4 只能算勉强过。

4.2 incast 最后一跳排队占比归因
  └─ 适合做前置练习（半天就能出数），但结论十有八九是
     「最后一跳占大头」，没有悬念。

6.1 路由收敛 vs 端侧切换的恢复时间
  └─ 有意思，但仿真里「路由收敛」的行为取决于你怎么建模，
     容易变成证明自己的假设。
```

### 2.3 淘汰区：十一个，附原因

```text
1.4 包级喷洒 + 选择性重传联合调优
  └─ 已被占位（Rondo, 2026-11；ALPS, IWQoS 2026），
     且门槛抬到了 FPGA 智能网卡与大规模仿真。C1 挂。

2.2 多级 Clos 哈希极化
  └─ 没有公开真实的交换机哈希规则，你只能假设一套规则再证明它有害。
     C3、C4 挂。

2.3 路径时延不等时喷洒的收益边界
  └─ Rondo 的动机段已经把这件事讲完了。C5 挂。

3.2 用机器学习预测拥塞
  └─ 训练集只能来自你自己的仿真器，模型学到的就是仿真器的偏置。
     结论无法证伪，C3 挂。这是最容易「忙一个月，得到一个假结果」的题。

3.3 接收端授权在 incast 下的收敛
  └─ 没有开源参考实现，你写出来的 RCCC 无法证明与规范一致。C3 挂。

4.3 Homa 式接收端授权移植到 AllReduce
  └─ 两个系统的语义不匹配（Homa 面向请求-响应，AllReduce 面向批量同步），
     四周内大概率卡在「怎么定义公平对比」。C3 挂。

5.2 800G 采样不足导致尾延迟漏检
  └─ 需要真实 800G 环境和可配置采样率的交换机。C1 挂。

5.3 带内遥测开销与可见度权衡
  └─ 需要往仿真器里加遥测头，再需要一个公认的「可见度」指标——
     这个指标目前没有共识。C2、C4 挂。

6.2 跨域 AllReduce 张量切分
  └─ 四周只能做出很粗的模型，结论不可信。C1、C3 挂。

6.3 Agent 任务可持久执行
  └─ 与网络协议关系浅，且需要真实任务系统才能验证副作用。C1 挂。
```

## 3. 第一名的四周日程（每周一个可验收产物）

```text
第 1 周｜把现象做出来
  做：在已有 Python 模型上加三样东西——乱序到达、接收端固定槽位、槽位耗尽即丢。
  跑：固定丢包率，槽位从 8 扫到 8192，看完成时间怎么变。
  交付：一张曲线（x = 槽位，y = 全员完成时刻）。
  卡点：如果曲线是平的，立刻进第 2 周的「上界在哪」改法，不要硬撑。

第 2 周｜把现象做成规律
  做：二维扫描（丢包率 × 槽位数），节点数固定 8 和 32 各跑一遍。
  算：有效重传率、误丢率，找出拐点。
  交付：一张图 + 三个数字（拐点位置、拐点前后的斜率、误丢率上限）。

第 3 周｜证明不是模型的伪影
  做：用 ns-3（或 ASTRA-sim 的 ns-3 后端）复现拐点前后各一个点。
  交付：两条独立来源的曲线叠在一张图上。
  降级方案：ns-3 跑不起来就退回纯 Python + 文献对照，
            在报告里明确标注「未在包级仿真验证」。这是可接受的降级。

第 4 周｜把结论说清楚
  做：写 6 页以内的报告，三张图，一段「这说明了什么、下一步该测什么」。
  交付：任何人拿着你的脚本和参数能复现同一张图。
```

## 5. 三条陷阱，以及我上一轮说错的一处

```text
错误 1｜我上一轮说「选择性重传 + 包级喷洒是真空档」，这条不成立。
  └─ 事实：Rondo 已在 2026-11-03 系统处理了喷洒下的重排序问题；
     ALPS（IWQoS 2026）把「丢包与乱序无法区分」列为四大挑战之一；
     UEC 1.1 也已把喷洒、路径切换、直接放置写进规范。
     结论：那个方向已从空档变成热门赛道，门槛抬到 FPGA 智能网卡。
     我撤回那条建议。新的第 1 名是它的下界：槽位耗尽之后会怎样。

错误 2｜把「能复现」当成「有贡献」。
  └─ 1.1 那个 demo 四问全过，但它不是选题，是训练器械。
     尺子必须带第五项，否则你会把复现当成果。

错误 3｜先在仿真里做出漂亮结果，再去找它对应现实中的什么。
  └─ 顺序反了。正确顺序是：先在公开数据里看见真实现象，
     再回仿真里复现它。这就是 5.1 存在的理由，别跳过。
```
