# X3 · 能力雷达

> 贯穿件。把 progress 里的原始记录，变成"哪一层会、哪一层不会、下一步练哪"。

---

## 一、为什么先做它而不是先做 X2

X2（故障注入台）是内容工程，X3 是把已有数据显性化。85 关跑完，数据已经在 `localStorage` 里躺着了，只差一层解释。

它解决的不是"多一个页面"，而是一个具体问题：**玩完 20 关的人，不知道自己弱在哪，也不知道下一步该点哪。**

## 二、一条公式，写死在代码与测试里

```
掌握度 = 通关率 × 70 + 一次过率 × 30
  通关率  = 该平面已通关卡 / 该平面总关卡
  一次过率 = 第一次提交就对的关卡 / 已通关卡
```

为什么不用"登录时长""做题数量"这类指标：它们能被刷。**一次过**是唯一一个"假装不了"的信号——反复试可以试出答案，但试不出第一次就想到。

为什么权重是 70/30：通关是底线（不会就是 0），一次过是熟练度。没通关时后一项直接乘 0，避免"乱点也算会"。

## 三、页面结构

```
顶部 KPI      通关 28 / 85   一次过 21   提交 46 次
雷达          七边形，七个轴 = 七个平面，越靠外越熟；轴上标 "L3 53"
右侧明细      七行：平面 / 名称 / 进度条 / 已通 / 掌握度
下一步        取掌握度最低且有未通关卡的平面，指向该平面第一个没通的关
错题本        最近 12 条未通过的关（模块 + 关卡 + 所在平面），点击直达
```

空状态：没有记录时给出两个直达入口（M00 / M03），并说明"这里只统计本机玩过的关卡，不做任何推测"。

清空记录：两次点击确认（第一次按钮变成"再点一次确认清空"），不用 `confirm()` —— 无头环境里 `confirm` 会卡住测试。

## 四、实现分层

```
src/core/ability.js     纯计算：progress 记录 → 七个平面 + 总体 + 下一步 + 错题本
tests/ability.test.js   10 项，公式写死在测试里
src/shell/app.js        只负责把计算结果画出来（SVG 七边形 + 列表）
```

计算层不碰 DOM，所以能在 Node 里直接测；界面层不做任何计算，改公式只改一处。

## 五、推荐逻辑

```
有未通关卡：按掌握度升序找最弱的平面 → 该平面第一个没通的关
            （掌握度并列时按平面顺序，所以全新用户会被带到 L0/M00）
全部通关：  找"一次过率最低"的平面，提示重刷，不硬塞新内容
```

一个刻意的取舍：**不推荐"随机再来一关"**。推荐的价值在于"有理由"，哪怕理由是"这层最弱"。

## 六、测试

```
node tests/ability.test.js      10 / 10
  · 空记录 → 七层全 0、判定 empty、下一步指向 M00/s1
  · 关卡总数与注册表一致（85）
  · 掌握度公式逐项核对（用 l0.total 推导，不硬编码关卡数）
  · 一次过 > 反复过（同样 1 关，tries=1 的掌握度更高）
  · 只尝试没通过 → done=0、mastery=0、仍算 empty
  · 汇总数字等于七层之和
  · 全部通关后转为"复练一次过率最低的层"
  · 错题本倒序、上限 12、能解析出模块与关卡名
  · 脏数据（不存在的模块/关卡）不崩

tests/ui.smoke.html    +4 项：雷达页打开、空状态引导、七行、有"下一步"
tests/ui.all.html      +5 项：跑完 85 关后 85/85、七行、建议复练、无错题本
```

## 七、这一轮挑出来的问题

```
1  测试硬编码了"L0 有 3 关"
   现象：掌握度期望 53，实际 42。
   原因：L0 是 M00 三关 + M01 三关 = 6 关，我写测试时只算了 M00。
   修法：用 l0.total 推导期望值。
   教训：测试里凡是"模块内数量"，都应该从数据取，不要凭记忆写死。

2  全量 UI 测试的进度没重置
   现象：同一份测试跑两次，"85/85"和"无错题本"两条断言忽真忽假。
   原因：file:// 的 localStorage 在同机重复运行时会被复用，上一轮的失败记录带进了下一轮。
   修法：ui.all 的第一步加 TopoProgress.reset()。
   教训：带持久化的测试必须先清场，否则断言就是掷骰子。

3  一条永远为真的占位断言
   现象：ui.all 里有一句 ok('平面页仍有 4 张卡', total === 0 || true)。
   原因：当时占位忘了删。这种断言比没有更糟——它制造"测试很全"的错觉。
   修法：删掉，换成雷达页的 5 条真断言。
   教训：`|| true` 出现在断言里，等于在这行写"我不打算测了"。

4  雷达形状看着不对（虚警）
   现象：截图里多边形顶点没到外环的 82%。
   排查：把 polygon 坐标导出来算半径，(200,82.7) 距圆心 103.3 = 0.82 × 126，完全正确。
   结论：是看图时的缩放错觉，不是 bug。这条留在这里，提醒"先量再改"。
```

## 八、明确不做

```
· 不预测"你适合什么岗位" —— 七维分数推不出这种结论，属于编
· 不和别人比 / 不做排行榜 —— 数据只在本机，也没有可比性
· 不记录每道题的用时 —— 用时会鼓励"快"而不是"对"
· 不自动清空 —— 记录是玩家的资产，只能由玩家自己删（两次点击确认）
```
