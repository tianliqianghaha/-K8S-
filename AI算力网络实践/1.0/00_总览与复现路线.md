# AI 算力网络 IPv6 实践 1.0（HPN-v6-Lab）· 总览与复现路线

> 一句话：**在三台普通云服务器上，用 IPv6 + SRv6/uSID 把 AI 高性能网络（HPN）的
> 四个目标——无损、超低 RTT、超高带宽、低抖动——拆成可证伪的实验，并跑出真数字。**

不需要 400G 网卡，不需要 RDMA 交换机，不需要 GPU。
需要的是：三台能加载内核模块、能建 network namespace 的普通云主机。

---

## 一、这套资料在回答什么问题

AI 训练集群的网络设计，本质上只在回答四个问题：

```
① 路径由谁决定？        交换机哈希碰运气，还是端侧点名
② 坏了怎么办？          等控制面收敛（秒级），还是端侧绕行（毫秒级）
③ 丢包的代价有多大？    大到必须用 PFC 做到不丢，还是可以用 SACK 扛
④ 流量长什么样？        大包带宽敏感，还是小包 RTT 敏感
```

四个问题分别对应四组实验。**每一组都能关掉某个机制、让指标立刻变差**——
这才叫证明，不叫演示。

## 三、四组实验分别证明什么

```
第一组  转发面：端侧点名，不靠哈希
  uSID 把整条物理路径编码进 128 bit 目的地址，零扩展头
  抓包可见：c 上同一条流的两帧，32 微秒内 DA 从 2:e000 左移成 e000
  验收：ping 4/4，RTT 0.48 ms，b 侧抓到双层 IP6 头且 SRH 计数 0

第二组  流量形态：小包和大包是两个世界
  a2a  1400 B → 80.1 Mbps / 7153 msg·s⁻¹      ← 延迟敏感
  a2a 60000 B → 681.9 Mbps / 1416 msg·s⁻¹     ← 带宽敏感
  p99/p50 从 2.6 倍涨到 300 倍 ← 训练看尾延迟的量化依据

第三组  传输策略：SACK 与喷洒值多少钱
  无丢包 515.8 Mbps → 2% 丢包 13.1 Mbps        ← 塌 25–40 倍，PFC 的存在理由
  同丢包 GBN 重传 12.17%、SACK 6.27%           ← 选择性重传省一半
  双平面喷洒 + SACK 20.2 Mbps（比单路径 +55%）
  双平面 + GBN 重传 20.48% —— 比单路径还差     ← 整窗回退会把好路也堵死

第四组  运维与故障：秒级收敛 vs 微秒级绕行
  三类故障谱：链路 down / 抖动 / 静默丢（接口 up 但包全丢）
  恢复时间量化、配置漂移回滚、班前五段巡检、21 条故障字典
```

## 四、复现顺序（半天能出第一条数据）

```
00  准备     三台同 VPC 同子网、都有 IPv6、安全组放行 ICMPv6 与实验 UDP 端口
01  体检     sudo ./bin/hpnlab check          （内核 ≥6.1、flavors、互通）
02  探路     sudo ./bin/hpnlab probe          （云平台允许什么，不测完别往下做）
03  建拓扑   sudo ./bin/hpnlab up
04  验收     sudo ./bin/hpnlab verify
05  流量     app/collsim.py 三台各起一个 rank
06  传输     app/mrctp.py 两端各起一个角色，配 30-fault.sh 注入丢包
07  巡检     ./bin/80-daily.sh --brief
```

云上必须额外做两件事，否则第 02 步一定失败（详见 `docs/04`）：

```
① 关闭三块主网卡的源/目的地址检查    SourceDestCheck=false
② VPC 路由表给每个 ULA 前缀加静态条目 NextHopType=Instance
```

原因：**VPC 内不是二层转发，是按 IPv6 目的地址路由**。邻居表里对端 MAC 全是
`ee:ff:ff:ff:ff:ff`（虚拟路由器），a 自己的 MAC 是 `00:16:3e:...`。

## 五、成本与时限

```
三台 ecs.e-c1m2.large 抢占式（2 vCPU / 4 GiB）   约 0.034 元/时/台
三台合计                                         约 0.10 元/时
一次完整跑通（建拓扑 + 四组实验）                  约 3–4 小时
单条数据（无丢包 vs 2% 丢包）                      约 10 分钟
```

安全组、VPC 路由、实例都是可回收的；**释放实例前必须先删那三条 ULA 路由**，
否则前缀会一直指向已释放的实例。

## 六、这套东西证明不了什么（写在最前面）

```
PFC 本身          没有交换机，产生不了真 pause 帧。
                  能证明的是"丢包的代价"，不是"PFC 的收益"。
芯片级 DLB/GLB    碰不到。本实验的等价物是端侧选路（MRC 路线，比芯片方案更激进）。
packet trimming   需网卡支持，这里用"立即 NACK"近似。
线速              400G/800G 无从谈起，所有吞吐都是相对值。
真 NCCL           没有 GPU，复刻的是流量形状与传输策略，不是集合通信算法。
IOAM6             iproute2 6.19 没带 ip ioam 子命令，带内遥测跳过。
```

一句话：**这是一个"机制可证伪、数字只可信相对关系"的实验台。**
