## 一、这台机器是哪个角色

```
node-a  headend   把包塞进外层 IPv6，路径直接写在 DA 里（无 SRH）
node-c  fabric    唯一做 uSID 弹栈的节点（DA 最左 16 bit 弹掉）
node-b  tailend   解封装，交付给本机协议栈（dummy 口 svc0）

a→b 直连 = 平面 1       a→c→b 绕行 = 平面 0
```

## 四、四组实验的最短命令

```bash
# ① 转发面：看 uSID 弹栈
#    c: tcpdump -i eth0 -nn -s200 -w /tmp/s.pcap 'ip6 and net fcbb:bb00::/24' &
#    a: python3 app/mrc_lite.py send --dst fd00:b0b0::1 --count 60 --plane 0
#    c: tcpdump -r /tmp/s.pcap -nn | awk '{print $3}' | uniq -c
#    期望：同一条流出现 2:e000 → e000 的位移，相隔几十微秒

# ② 流量形态（三台各起一个 rank，后台拉起）
for r in 0 1 2; do
  setsid nohup python3 app/collsim.py run --pattern a2a --rank $r \
    --peers <a>,<b>,<c> --port 12110 --size 60000 --count 200 > /tmp/c$r.json 2>&1 &
done

# ③ 传输策略（b 起接收，a 起发送，按端口打伤平面 1）
#    b: setsid nohup python3 -u app/mrctp.py run --role recv --peer <a> --port 9600 --msg-mb 1 &
#    a: ./bin/30-fault.sh inject lossport 2 9601
#       python3 app/mrctp.py run --role send --peer <b> --port 9600 --port1 9601 \
#         --msg-mb 1 --msgs 20 --paths 1 --retx sack --nack on
#       ./bin/30-fault.sh clear

# ④ 故障注入（只打实验流量，SSH 不断）
./bin/30-fault.sh inject loss 100        # 按 uSID 目的地址，平面 0 全丢
./bin/30-fault.sh inject lossport 2 9601 # 按 UDP 目的端口，只打平面 1
./bin/30-fault.sh inject jitter 20 5     # 时延 20ms ±5ms
./bin/30-fault.sh clear
```

## 五、三条自查判据（一眼定生死）

```
IPv6 通不通      ping -6 -c3 <对端>      → 不通先查安全组 ICMPv6
uSID 通不通      ping -6 -c3 fcbb:bb00:ffff:1::1
                 不通 → ① SourceDestCheck 关了没 ② VPC 路由表加了没
拓扑在不在       ip -6 route show | grep seg6local    → 空就是 up 没跑成
```

## 六、停止与恢复

```
停止
  ./bin/30-fault.sh clear               清注入
  pkill -9 -f '[c]ollsim.py'            清实验进程
  tc qdisc del dev eth0 root            彻底清队列（clear 已含）

恢复
  ./bin/hpnlab up && ./bin/hpnlab verify

重建最短路径（换机器时）
  1) 三台放同一份代码
  2) 改 conf/lab.env：ROLE + 三个地址
  3) ./bin/hpnlab check → probe → up → verify
```

## 七、释放云资源前必须做（顺序不能反）

```
1) 删掉 VPC 路由表里的三条 ULA 条目
   fcbb:bb00:2::/48  /  fcbb:bb00:e000::/48  /  fcbb:bb00:ffff::/48
2) 确认删干净：DescribeRouteEntryList 或控制台路由表页
3) 再释放实例
   ── 反了会留下一堆指向已释放实例的黑洞路由，下次开机会莫名不通
```

## 八、最容易踩的五个坑

```
① 安全组只放 TCP/UDP 不放 ICMPv6     → IPv6 连邻居解析都过不去，表现为"配了但 ping 不通"
② 只看"VPC 开了 IPv6"就以为能用      → 交换机也要有 IPv6 网段，两个是两件事
③ 用 ECS 端点查 Ipv6CidrBlock        → 查不到，必须走 vpc.aliyuncs.com + 2016-04-28
④ fault clear 无条件删路由            → 会把正常外层路由一起删（已修，见 docs/03 第 16 条）
⑤ tc 直接挂 root netem                → 单网卡上会把 SSH 一起打断，必须 prio + u32 过滤
```
