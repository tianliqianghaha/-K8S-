```

  fd00:b0b0::1  encap seg6 mode encap.red segs 1 [ fcbb:bb00:e000:: ] dev eth0
  fcbb:bb00:2::/48     via ...:f9a6 dev eth0        ← 到 c
  fcbb:bb00:e000::/48  via ...:f9a5 dev eth0        ← 到 b
  default via fe80::ecff:ffff:feff:ffff             ← VPC 虚拟路由器

两张策略表（端侧选路的地基）
  table 100  fd00:b0b0::1 encap.red segs 1 [ fcbb:bb00:2:e000:: ]   ← 平面 0（经 c）
  table 101  fd00:b0b0::1 encap.red segs 1 [ fcbb:bb00:e000:: ]     ← 平面 1（直达 b）

策略规则
  fwmark 0x2 lookup 100 priority 200
  fwmark 0x1 lookup 101 priority 201
```

这一个节点就是 MRC 里"EV 表"的软件等价物：
**程序打 fwmark → 内核查表 → 换外层 DA → 包走不同物理路径。**

## 六、如果以后要重建，最短路径

```
1) 开三台同规格实例（同 VPC、同子网、同可用区、都要 IPv6）
2) 安全组：三条规则，IPv6 来源必须写在 Ipv6SourceCidrIp
3) 三块主网卡关源/目的检查   SourceDestCheck=false
4) VPC 路由表加 3 条 ULA 静态条目  NextHopType=Instance
5) 三台放同一份代码，改 conf/lab.env（ROLE + 三个地址）
6) ./bin/hpnlab check → probe → up → verify
```

第 3、4 步是这套东西在云上能不能成立的**唯一前提**：
VPC 内不是二层转发（邻居表里对端 MAC 全是 `ee:ff:ff:ff:ff:ff`），
自定义 DA 必须靠 VPC 路由表显式指路。
