# 实验体系总览 · 面向 AI 算力网络集群

> 这一册解决一个问题：**别凭兴趣做实验，按岗位能力做。**
> 40 个实验全部来自真实 JD 的能力要求，按 8 层组织，每一层都能独立验收。

---

## 1. 能力域：从 12 份 JD 里提炼出来的硬要求

我读了国内（智联/猎聘）和海外（NVIDIA 生态、AI 实验室）这类岗位的描述，
去重之后剩下的就是下面 12 条。**凡是 JD 里反复出现、又能在三台机器上证伪的，才收进体系。**

```
C1  架构设计      Leaf-Spine / Fat-Tree / Multi-Rail / 收敛比 / 故障域划分
C2  协议深度      RoCEv2 / SRv6 uSID / BGP / EVPN / IPv6 单栈
C3  无损与拥塞    PFC / ECN / DCQCN / QoS 分级 / buffer 调优
C4  负载均衡      ECMP / 自适应路由 / 端侧确定选路 / 哈希熵
C5  集合通信      AllReduce / AllToAll / 流水并行 / 并行策略对网络的影响
C6  性能测试      perftest / nccl-tests / iperf / 基准与跨节点验收
C7  故障定位      抓包 / 分层排除 / 灰故障 / RCA
C8  可观测与容量  遥测 / 队列深度 / 基线 / 容量分析
C9  自动化交付    Python / Ansible / 配置即代码 / 变更回滚
C10 多租户与安全  VRF / ACL / 网络分区 / 管理面隔离
C11 文档与交付    SOP / 验收报告 / 故障案例库
C12 前沿跟踪      UEC / DPU / CXL / APN6 / 数字孪生
```

一句话看差距：**只做"能 ping 通、能跑 SRv6"是不够的**，JD 里权重最高的是 C3（无损拥塞）
和 C7（故障定位），而这两块恰好是最难在云上模拟、也最能拉开差距的地方。

## 2. 八层结构：从"包能走"到"集群能扛"

```
L8 前沿层      E35-E40   UEC/MRC 传输、APN6、带内遥测、数字孪生、单栈迁移、数据面卸载
      ▲
L7 租户安全    E32-E34   VRF 切片、ACL 分区、管理面隔离
      ▲
L6 可观测      E28-E31   逐流统计、排队点定位、时延分解、时钟同步
      ▲
L5 故障韧性    E24-E27   故障谱、灰故障、恢复时间、配置漂移
      ▲
L4 业务流量    E19-E23   Ring/Tree AllReduce、AlltoAll、PP、KV cache、混跑
      ▲
L3 负载均衡    E14-E18   哈希极化、端侧选路、大流小流、rail 局部性、故障域
      ▲
L2 队列拥塞    E09-E13   ECN 阈值、队列深度、incast、慢排空、丢包敏感度
      ▲
L1 转发协议    E04-E08   单栈、uSID、flavor 对比、PMTU、NDP
      ▲
L0 地基        E01-E03   能力矩阵、通透性探路、基线
```

**为什么必须自下而上**：L2 的每一个结论都依赖 L1 的路径是确定的；
L4 的每一个流量结论都依赖 L2/L3 的队列和选路是可控的。
跳层做实验，量出来的数不可解释。

## 4. 三条推荐路线

### 路线 A · 面试冲刺（3 天，8 小时）

```
Day1  E01 → E02 → E05 → E14       拿到"能讲清 uSID 与哈希极化"的底气
Day2  E09 → E13 → E15 → E19       拿到"拥塞 + 集合通信"的量化结论

```
"Perftest 好但 NCCL 上不去怎么查"    → E13 + E19 + E29

## 5. 每个实验的记录格式（强制）

不做记录的实验等于没做。每个实验必须留下这七项，缺一项就算没完成：

```
1. 编号与名称
2. 假设（一句话，必须可证伪）
3. 变量（改了什么，其他保持不变的清单）
4. 原始数据（命令输出 / pcap / CSV，落盘到 /var/lib/hpnlab）
5. 结论（用数据说话，不用形容词）
6. 边界（这个结论在什么条件下不成立）
7. 踩到的坑（写进 docs/03 故障字典）
```

第 6 项最容易被跳过，但它恰恰是面试时最值钱的部分——"我知道这个结论什么时候不成立"。

## 6. 哪些东西这三台机器永远证不了

先把话说死，避免写出注水的报告：

```
├─ PFC 的真实行为（无反压源）        → 只能证"丢包的代价"，E13
├─ 芯片级 DLB/GLB/自适应路由          → 只能证"端侧选路的收益"，E15
├─ 线速 400G/800G、光层健康          → 只能比相对值
├─ 真实 NCCL 性能（无 GPU）           → 只复刻流量形状，E19-E22
├─ packet trimming                   → 只能近似（截断后丢）
└─ DPU/IPU 卸载                      → 只能用 XDP 近似，E40
```

配套的诚实写法：
```
"本实验证明的是机制方向与相对差异，绝对值受限于虚拟网卡与共享出口带宽，
 不构成对生产性能的预测。"
```
