## 2. 四个坑，按踩到的顺序

### 坑 1：ECS 端点读不到 IPv6 字段（我误判"你没开 IPv6"）

```
现象
  DescribeVpcs / DescribeVSwitches（走 ecs.aliyuncs.com）返回的
  Ipv6CidrBlock 是 null，控制台里却明明有 240b:...::/56

根因
  ECS 端点的这两个接口不返回 IPv6 字段。
  必须走 VPC 端点：https://vpc.aliyuncs.com/  Version=2016-04-28

处置
  ecs.py 里 describe_vswitches 改走 _vpc_call；
  读不到时再调 DescribeVSwitchAttributes 兜底
```

### 坑 2：RunInstances 的 Ipv6AddressCount 被静默忽略（假象）

```
现象
  请求体里确实有 Ipv6AddressCount=1（审计日志可查），
  但 DescribeInstances 里 Ipv6Address=null、网卡 Ipv6Sets=null

真相
  IPv6 其实分配成功了。DescribeInstances 本身就不返回这个字段，
  唯一可靠的来源是 DescribeNetworkInterfaces 的 Ipv6Sets

处置
  新增 describe_instance_ipv6()，创建后用网卡接口回读
  另一个佐证：再调 AssignIpv6Addresses 会报
  InvalidOperation.Ipv6CountExceeded（说明已经有 1 个了）
```

### 坑 3：安全组的 IPv4 规则不覆盖 IPv6（最隐蔽）

```
现象
  安全组 12 条入站规则，看着有 ALL + ICMP，"应该全通了"

真相
  带 Ipv6SourceCidrIp 的规则：0 条。
  IPv4 的 ALL 规则对 IPv6 流量完全不生效，缺 ICMPv6 会导致
  邻居发现（NDP）直接失败 —— 表现是"地址配上了但 ping 不通"

处置
  新建专用安全组 hpn-v6-lab-sg，三条规则：
    ALL    240b:4001:1ed:2e02::/64   实验台内网
    ICMPv6 ::/0                       PMTU + 排障
    TCP22  0.0.0.0/0                  SSH
  并且把"只算带 IPv6 来源的规则"写成了单测
```

### 坑 4（最关键）：VPC 内不是二层转发，自定义目的地址会被丢

```
现象
  a 抓包：3 个包发出去了，DA = fcbb:bb00:ffff:1::1
  c 抓包：0 个包
  ping 100% 丢包

根因（两层）
  ① ENI 的 SourceDestCheck=True：只允许"源或目的地址是本实例 IP"的报文
     → 目的地址是 ULA 的包在出网卡时就被丢
  ② 关掉之后仍然不通。看邻居表：
       fcbb → 对端 lladdr 全是 ee:ff:ff:ff:ff:ff（标记 router）
     a 自己的 MAC 是 00:16:3e:15:7d:74
     → 同子网内所有包都发给 vSwitch 的虚拟路由器，由它按 IPv6 目的地址转发
     → ULA 不在 VPC 网段里，路由器没有路由，直接丢

处置（两个都要做）
  ① 关闭源/目的检查
     ModifyNetworkInterfaceAttribute SourceDestCheck=false   （三块主网卡）
  ② 在 VPC 路由表里给 uSID 前缀指定下一跳
     CreateRouteEntry RouteTableId=vtb-j6c4mn7ednm7qq9fsbhyg
       DestinationCidrBlock=fcbb:bb00:2::/48     NextHopType=Instance  NextHopId=i-...jdn  (c)
       DestinationCidrBlock=fcbb:bb00:e000::/48  NextHopType=Instance  NextHopId=i-...jdm  (b)
       DestinationCidrBlock=fcbb:bb00:ffff::/48  NextHopType=Instance  NextHopId=i-...jdn  (c)
     注意：NextHopType 不能用 NetworkInterface
           → OperationUnsupported.Ipv6EntryOnPrimaryNetworkInterface
           主网卡只能用 Instance 作为下一跳

结果
  ping fcbb:bb00:ffff:1::1 → 4/4 收到，RTT 0.48ms，c 抓到 4 个包
```

> **这个坑的教学价值最高**：它说明"静态源路由"在云上不是免费的，
> 你要在 VPC 路由表里为每个 SID 前缀铺一条静态条目 ——
> 这恰好和 MRC 论文里"交换机装静态表、不做动态路由"是同一个思路，
> 只不过这里干这活的是 VPC 的虚拟路由器。

## 3. 端到端验证证据

### 3.1 平面 1（直达）：封装 + 解封装

```
b 上抓包（3 个包，SRH 计数 0）：
  240b:...:f9a7 > fcbb:bb00:e000:::  IP6 240b:...:f9a7 > fd00:b0b0::1: ICMP6, echo request
  ↑ 外层 DA          ↑ 内层 DA（业务地址）
```

### 3.2 平面 0（绕行）：uSID 真的被弹掉了

```
c 上抓包，同一条流的两帧，相隔 32 微秒：
  11:17:27.674951  > fcbb:bb00:2:e000::    ← 进 c，DA 带中转段 0002
  11:17:27.674983  > fcbb:bb00:e000::      ← 出 c，0002 已弹掉，整体左移 16 bit
```

### 3.3 验收结果

```
a（headend）  10 项通过 0 失败   路由 / 策略路由 / 双平面选路 / 端到端 ping
b（tailend）   4 项通过 0 失败   svc0 地址 / End.DT6 / 抓到包 / 无 SRH
c（fabric）    3 项通过 0 失败   转发 / next-csid / 弹栈后路由
```

## 4. 节点上的部署方式（不依赖 SSH 密码）

```
为什么不用 SSH
  实例是运行期生成随机 root 密码，本机没有 sshpass；
  改用云助手（Cloud Assistant）在实例内执行命令。

关键点
  ├─ 动作名是 RunCommand，不是 SendCommand（后者是 SWAS 的名字）
  ├─ 必须 POST，GET 会返回 InvalidAction.NotFound
  ├─ 必须用地域端点 https://ecs.cn-hongkong.aliyuncs.com/
  └─ CommandContent 单条上限约 16KB，实验台 36KB → 分 5 段 base64 追加

分发方式
  hpn1 分片上传 → 起 python3 -m http.server 8000 --bind ::
  → hpn2/hpn3 通过 IPv6 直接 curl 拉取（顺便验证了内网 IPv6 通）
  → 三台各自 cp nodes/<name>/lab.env conf/lab.env
```

## 5. 现在可以直接跑的实验

```
三台都在 /opt/hpn-v6-lab3

sudo ./bin/hpnlab check          # 已全绿
sudo ./bin/hpnlab up|down|status # 拓扑
sudo ./bin/hpnlab verify         # 验收
sudo ./bin/hpnlab rtt 200        # 时延分布
sudo ./bin/hpnlab fault inject jitter 20 5
sudo ./bin/hpnlab send --dst fd00:b0b0::1 --plane both --count 2000
sudo ./bin/hpnlab recv --count 2000
```

### 清理顺序（重要）

```
1) 三台 ./bin/hpnlab down
2) 删 VPC 路由（否则 ULA 前缀会一直指向将被释放的实例）
   DeleteRouteEntry × 3
3) 释放实例
   python scripts/cli.py release --instance-id i-xxx --confirm --force
4) 删安全组 sg-j6ce83xhynyybp9fc1rd
5) （可选）恢复 SourceDestCheck=true
```

## 6. 仍未验证 / 已知限制

```
├─ IOAM6：ip ioam 子命令不存在（iproute2 6.19 未带该子命令），L9 暂不可用
├─ PFC：物理上没有，永远无法证明
├─ 两条平面共享同一块 eth0 与同一个 vSwitch，带宽不独立
├─ 抢占式实例随时可能被回收（无保护期），实验数据要及时落盘
└─ ULA 前缀依赖 VPC 路由表条目，换 VPC/交换机必须重铺
```
