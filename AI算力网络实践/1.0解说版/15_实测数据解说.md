# 15 · 实测数据解说（reports/实测数据-2026-11-25.md）

> 对应文件：`reports/实测数据-2026-11-25.md`

这份报告只有一个原则：**每条数字都带边界，证明不了的直接写"证明不了"。**

---

## ① 为什么"带边界"比"数字大"重要

```
没有边界    "吞吐 515 Mbps"
            → 读者会以为是网络能力，拿去做容量规划 → 出事

带边界      "吞吐 515 Mbps，是 Python 用户态上限，不是网络上限；
            可比的是同一环境下的相对关系（25–40 倍塌陷）"
            → 读者知道能引用什么、不能引用什么
```

一个数字如果不写清楚"在什么条件下成立"，它就不是数据，是噪音。

## ② 报告七章，每章一个层次

```
0  环境            节点、内核、缓冲
1  转发面          uSID 到底做了什么（三个证据）
2  流量形态        四种形状 + 大小扫描
3  传输策略        六组对照 + 三个结论 + 边界
4  故障与运维      已验证的部分
5  证明不了的事    ★ 放在最前面也好、中间也好，必须有
6  复现路径        别人怎么重跑
7  一句话汇总      能对外讲 / 不能对外讲
```

第 7 章的分法是刻意设计的：**把"能讲"和"不能讲"分开列。**
因为对外交流时最容易出的错，是把"不能讲"的东西讲了。

## ③ 三个最值得引用的数字

### 3.1 515.8 → 13.1 Mbps（塌 25–40 倍）

```
条件   1 MB 消息 × 20 条，单路径，SACK，RTO 300 ms
变量   丢包率 0%  vs  2%
结论   2% 随机丢包就把有效吞吐打到 1/40
意义   这就是 PFC 存在的全部理由：
       无损网络不是优化，是"能不能跑"的问题
```

### 3.2 12.17% vs 6.27%（重传量差一倍）

```
条件   同样 2% 丢包，单路径
变量   Go-back-N  vs  SACK
结论   GBN 重传率是 SACK 的两倍，且多出来的几乎全是伪重传（2032 vs 935）
意义   伪重传在真实集群里会变成额外拥塞，反过来再触发更多丢包
```

### 3.3 20.48%（最反直觉）

```
条件   双平面喷洒 + GBN + 平面 0 丢 2%
结论   重传率 20.48%，比单路径 GBN 的 12.17% 还高
原因   整窗回退不看路径，把没受伤那条平面上的好包也重发了一遍
意义   多路径必须配选择性重传，否则不如不喷
```

第 3.3 条是整套实验里最有洞察力的一条，因为它推翻了一个直觉：

```
直觉   多路径 = 更可靠
真相   多路径 + 错误的重传策略 = 更糟
```

## ④ 报告里最诚实的两段

### 4.1 版本演进：v1 的数据为什么作废

```
v1   3.2 Mbps，重传 39%，六种配置差异 < 3%
     根因：接收端每包 O(n) 找洞 + 每包都发 NACK
           → 发送端被自己打爆，39% 全是自发重传

v2   570 Mbps，重传 0.27%
v3   加按端口分平面，才第一次看到"喷洒 vs 单路径"的差异
```

报告里那句话值得抄下来：

> **v1 那组"配置之间没差异"的数据不是网络没差异，是测量工具坏了。**

把作废的数据和作废的原因一起写进报告，比删掉它更有价值——
因为下一个人可能正在犯同样的错。

### 4.2 "本环境证明不了的事"

```
PFC 本身            没有交换机，产生不了真 pause 帧
芯片级 DLB/GLB      碰不到
packet trimming     需网卡支持，用立即 NACK 近似
线速                400G/800G 无从谈起
真 NCCL             没有 GPU
IOAM6               iproute2 6.19 没带 ip ioam 子命令
```

六条，一条都不含糊。这一节的存在本身就是一种态度：
**我知道我的结论到哪里为止。**

## ⑤ 报告里一个容易忽略的细节

第 4 章有一段"按端口过滤的偏移是实测出来的，不是算出来的"：

```
偏移 40   丢 0 包
偏移 41   丢 100 包
偏移 42   丢 100 包    ← 正确
偏移 43   丢 100 包
```

为什么要把这个试错过程写进报告？

```
因为它说明"标定过"和"算出来"是两件事。
理论上偏移是 42（IPv6 头 40 + UDP 源端口 2），
但偏移 40、41、43 的表现并不完全相同——
不实测就不知道 40 是错的。
```

**报告里保留"我怎么知道的"，比只写"是什么"更有说服力。**
