## 一、这套东西一句话

**用三台普通云服务器，把 AI 训练网络（HPN）的四个目标——
无损、超低 RTT、超高带宽、低抖动——拆成可证伪的实验，并跑出真数字。**

不需要 400G 网卡，不需要 RDMA 交换机，不需要 GPU。
三台 2 核 4G 的抢占式实例，一小时三毛钱。

---

## 二、为什么不能"复刻"，只能"拆解"

```
没有交换机     → 产生不了真的 PFC pause 帧
没有 RDMA 网卡 → 只有软件 rxe，慢一个数量级
没有 GPU       → 跑不了 NCCL
共享 eth0      → "线速"无从谈起
```

所以正确做法不是"复刻性能"，是**把每个设计决定翻译成一个能测的代理量**：

```
HPN 的目标      翻译成什么              用什么测
无损            丢包的代价              tc netem 丢包 + 重传统计
超低 RTT        时延分布不是平均值      ping / 逐包间隔 p50 p99
超高带宽        相对吞吐 + 链路利用率   自研喷洒程序逐段计数
低抖动          尾延迟、乱序率          包间隔分位数、乱序计数
```

**这才是这套东西能成立的原因：它不追求"像"，它追求"关掉它指标会变差"。**

## 五、读完你应该能回答的五个问题

```
① 为什么用 uSID 而不是标准 SRv6？
   因为云 vSwitch 会剥 SRH，uSID 没有 SRH 可剥；顺带把每跳 16 字节的
   开销压掉，小包有效载荷率从 36% 提到 57%。

② 为什么"买了双平面还是跑满一条"？
   哈希极化：ECMP 只看五元组，同源宿的多条流会撞到同一条链路。
   IPv6 的 Flow Label 是免费熵，不用白不用。

③ 2% 丢包到底有多严重？
   有效吞吐塌 25–40 倍。这是 PFC 存在的全部理由。

④ 多路径喷洒一定更好吗？
   不一定。配 SACK 快 55%，配 Go-back-N 反而最差（重传 20.48%）。

⑤ 这套东西证明不了什么？
   PFC 的收益、线速、真 NCCL、芯片级 DLB/GLB、packet trimming。
```

## 六、读的时候注意三件事

```
① 每篇末尾都有一句"一句话记住这一篇"
   时间紧就只读那一句，但别只看那一句。

② 凡是标"边界"的段落，一个字都别跳
   因为它告诉你这个结论什么时候不成立——这才是面试和实战里最值钱的部分。

③ 凡是标"踩坑"的段落，都是真实发生过的
   不是从网上抄的常见问题，是这套环境里真的把人坑过的东西。
```
