# 06 · 多路径原型解说（mrc_lite.py）

> 对应文件：`app/mrc_lite.py`

这是三个程序里最简单的一个，作用是**先把"端侧逐包选路"这件事跑通**，
为后面更复杂的 mrctp（带 SACK 重传）打地基。

---

## ① 它要证明的一句话

**同一个目标地址，程序可以让它的每一个包走不同的物理路径。**

```
不用它的时候：一个目的地址 → 一条路由 → 一条路径（哈希碰运气）
用它的时候：  一个目的地址 → 每个包打不同 fwmark → 不同路由表 → 不同路径
```

这就是 MRC 论文里"EV（熵值）表"的软件版本。

---

## ② 两个角色

```
recv   绑一个地址和端口，收包，统计乱序率、丢包率、平面分布
send   按指定策略发包，包里带序号和平面号
```

包格式很简单：

```
!QQB   seq(8B)  send_ns(8B)  plane(1B)     然后补零到指定大小
```

序号是干什么的？**没有序号就没法统计乱序和丢包。**

```
收到 seq=5 之后又收到 seq=3  → 乱序
连续收到 1,2,4,5 缺 3       → 丢包
```

### 2.1 一个必须注意的坑：不能跨机相减时间

`send_ns` 用的是 `time.monotonic_ns()`。它的值在不同机器上**起点不同**：

```
a 的 monotonic 可能是 1.2e15
b 的 monotonic 可能是 8.4e14
两个相减 → 负数或者几百万秒，毫无意义
```

所以程序**只用它算本地 RTT**（同一个进程内收发），跨机只统计：
乱序率、丢包率、平面分布、本地收包间隔。

这条约束后来在 mrctp 和 collsim 里都被严格遵守。

---

## ③ 选路是怎么实现的

```
① 路由层已经准备好（20-topology.sh 做的）
   mark 0x2 → 表 100 → 外层 DA = fcbb:bb00:2:e000::
   mark 0x1 → 表 101 → 外层 DA = fcbb:bb00:e000::

② 程序在 socket 上打标记
   s.setsockopt(socket.SOL_SOCKET, SO_MARK, 0x2)

③ 内核发这个包时，按 mark 查规则 → 查对应表 → 用对应 DA 封装出去
```

所以 mrc_lite 的核心代码只有几行：

```python
def emit(...):
    mark = marks[rr % len(marks)]      # 轮转：这个包走哪条平面
    s.setsockopt(SOL_SOCKET, SO_MARK, mark)
    s.sendto(pkt, (dst, port))
```

`--plane 0|1|both` 就是控制这个轮转：

```
--plane 0    全部走平面 0（经 c 绕行）
--plane 1    全部走平面 1（直达 b）
--plane both 逐包轮转，一半一半
```

---

## ④ 它跑出来的两个用途

### 4.1 证明"喷洒真的分到了两条路"

在 c 上抓包，`--plane 0` 时能看到流量经过 c；`--plane 1` 时看不到。
c 上抓到的包数 ≈ 总包数的一半，就是喷洒生效的直接证据。

### 4.2 给 uSID 弹栈做载体

这个程序发出去的包，外层 DA 就是 `fcbb:bb00:2:e000::`。
在 c 上抓同一个流的两帧，能看到：

```
11:17:27.674951  > fcbb:bb00:2:e000::    ← 进 c
11:17:27.674983  > fcbb:bb00:e000::      ← 出 c（左移 16 bit）
相隔 32 微秒
```

**这是整套实验里最硬的一条证据**，而它是由这个最简单的程序产生的。

---

## ⑤ 边界

```
① 用户态发不了线速
   单流几百 Mbps 量级，且受 CPU 单核限制
   → 只报相对值，不报绝对带宽

② 没有拥塞控制
   发多快完全由 --rate 决定，不看网络反应
   → 所以它只能验证"路径可控"，不能验证"拥塞控制"

③ 没有重传
   丢了就是丢了，统计里能看到，但不会补
   → 补洞的能力在 mrctp.py 里
```

---

## ⑥ 怎么用

```bash
# 本机自测（不用拓扑）
python3 app/mrc_lite.py recv --bind ::1 --port 9998 --count 100 --idle 2 &
python3 app/mrc_lite.py send --dst ::1 --port 9998 --count 100 --plane both

# 真机：b 收，a 发
#   b: python3 app/mrc_lite.py recv --bind :: --port 9999 --count 2000
#   a: python3 app/mrc_lite.py send --dst fd00:b0b0::1 --port 9999 \
#        --count 2000 --plane both --rate 300

# 带 DSCP（给 QoS 实验用）
python3 app/mrc_lite.py send --dst fd00:b0b0::1 --plane 1 --dscp 46
```

## ⑦ 一句话记住这一篇

**mrc_lite 用"打 fwmark → 选路由表 → 换外层 DA"三行代码，
把"端侧逐包选路"从概念变成能抓包的事实；它是 uSID 弹栈证据的载体。**
