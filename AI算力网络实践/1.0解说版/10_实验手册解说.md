> 对应文件：`docs/02-实验手册.md`（L0–L9 基础）、`docs/06-实验手册-进阶篇.md`（E01–E40 进阶）

两份手册的分工：

```

          L0 探路 → L2 双平面 → L9 带内遥测（越往上越"运维/定位"）
docs/06   四十个进阶实验，按"八层 × 十二能力域"重排

```

## ① 为什么基础手册是 L0 到 L9 这条顺序

```
L0  探路        云网络到底允许你做什么        ← 不测完，后面全是空中楼阁
L1  基线        先证明你真的在跑 IPv6        ← 排除"其实是 IPv4 通"
L2  双平面      整个实验台的心脏
L3  MTU 黑洞    运维最经典的一课
L4  哈希极化    为什么"买了双平面还是跑满一条"
L5  端侧指定路径 把"运气"换成"确定"
L6  丢包与隔离  一条路径坏了会怎样
L7  故障谱      三种坏法，三种排查难度
L8  拥塞与尾延迟 平均值骗人
L9  带内遥测    把"哪一跳堵了"变成可测量
```

这个顺序不能打乱，因为**每一步都在验证下一步的前提**：

```
L0 不过 → 外层 DA 不能自定义 → L2 整章作废
L1 不过 → 你以为在测 IPv6，其实在测 IPv4 → 所有结论作废
L2 不过 → 后面所有"双平面"实验都退化成单路径 → 结论全部无效
```

这套实验台曾经真实发生过"L2 的半条路径被清理脚本误删"的事故，
结果是"双平面喷洒怎么调都没效果"——**前提错了，后面全是噪声。**

## ② docs/06 的七段格式，为什么第七段最值钱

每个实验都强制写这七样：

```
假设    一句可证伪的话（"关掉 X，Y 会变差"）
变量    这次只改什么，其他保持不变的清单
步骤    可直接粘贴的命令
观测    看哪几个指标
判据    什么数值算通过
边界    这个结论在什么条件下不成立
踩坑    我实际踩过的坑
```

前六段是标准动作，第七段（边界）最能区分人：

```
只有结论的人          "SACK 比 GBN 好一倍"
有边界的人            "在本环境（Python 用户态、固定 RTO、无拥塞控制）下，
                      SACK 的重传量是 GBN 的一半；绝对吞吐不可引用"
```

面试里真正拉开差距的，就是第二句话。

## ③ 六个值得单独讲的实验

### 3.1 L3 MTU 黑洞

```
做法   ping -6 -M do -s <超过 MTU 的载荷>
判据   小包通、大包不通 = 典型 PMTU 黑洞
处置   查 ICMPv6 Packet Too Big 是否被拦（云安全组最容易漏）
```

为什么它经典：**它表现为"网络时通时不通"，而且小流量永远不暴露。**
很多人第一次遇到会怀疑路由、怀疑 DNS、怀疑应用。

### 3.2 L4 哈希极化

```
做法   fib_multipath_hash_policy=0（只哈希 src/dst/flow label/nh）
       同源宿开 4 条流，看链路利用率
判据   4 条流全撞同一条链路 = 哈希极化
处置   policy=3（把 flow label 纳入），或端侧主动给每条流换 flow label
```

这是"买了双平面还是跑满一条"的根因。
**IPv6 的 Flow Label 就是送给负载均衡的免费熵**，不用白不用。

### 3.3 L8 拥塞与尾延迟

```
做法   8 打 1 做 incast，看平均 RTT 与 p99
判据   平均涨 20%，p99 涨 10 倍
结论   训练的性能由尾延迟决定，不由平均值决定
```

这一条是整个实验体系里最"反直觉"的：**平均值看起来正常的链路，训练可能在掉速。**

### 3.4 E19–E21 三种流量形态

```
ring / tree / pipe，三个 rank 后台拉起
ring 4/4 全通，tree 2/2/1/1，pipe 端到端 26.1 ms
```

### 3.5 E20 消息大小扫描（最值得背的一张表）

```
256 B    → 70.9 Mbps / 6328 msg/s      ← 延迟敏感
60000 B  → 681.9 Mbps / 1416 msg/s     ← 带宽敏感
p99/p50 从 2.6 倍涨到 300 倍
```

### 3.6 E35 MRC 传输与 SACK

```
2% 丢包 → 吞吐塌 25–40 倍
SACK 重传量是 GBN 的一半
喷洒 + SACK 快 55%
双平面 + GBN 反而最差（20.48%）
```

## ④ 两份手册怎么配合使用

```
第一次搭环境       docs/02 L0 → L2，必须按顺序
摸清楚机制         docs/02 L3 → L9
按岗位补短板       docs/06，看能力域索引挑
要出数据           docs/06 里标了"脚本"的那几个
```

三条推荐路线（在 docs/05 里）：

```
面试冲刺（3 天）  E01 → E05 → E14 → E09 → E19 → E24
完整跑通（2 周）  八层从上到下
专项深挖          只挑某一层，比如"负载均衡"那一层的 E14–E18
```

## ⑤ 手册里最容易被跳过、但最重要的一节

`docs/02` 最后一节是"记录模板（每个 Lab 填一遍）"。

```
为什么必须填
  不记录 = 没做。三天后你只记得"好像跑过"，
  但说不出是几号跑的、当时丢包率多少、结论是什么。
```

模板要求的东西很少：日期、目标、变量、关键数字、结论、边界。
**但它是"实验"和"折腾"的分界线。**
