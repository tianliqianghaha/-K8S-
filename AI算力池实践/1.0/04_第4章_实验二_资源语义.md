# 04 · 第 4 章 实验二：资源语义（调度是真的）

> 本章目标：把接入机制从应用层换到内核层，验证 K8S 对 GPU 的资源语义——
> 要 1 卡能跑、要 2 卡就 Pending、配额能卡死、抢占能踢人、假共享会出事、断网有明确时序。
> 前置条件：第 2 章 `nvidia.com/gpu=1` 已上报、taint 已打。
> 注意：本章需要腾空显存，先把第 3 章的 vLLM 与 Agent 停掉。

---

## 一、开工前：腾卡

```bash
sudo systemctl stop ai-agent vllm
sleep 3
sudo ctr -n k8s.io task kill -s SIGKILL vllm-server 2>/dev/null
sudo ctr -n k8s.io task delete -f vllm-server 2>/dev/null
sudo ctr -n k8s.io container delete vllm-server 2>/dev/null

nvidia-smi --query-gpu=memory.used --format=csv,noheader     # 应回落到 300MiB 左右
```

本章做完再按第 3 章 3.5/3.6 把服务起回来。

## 二、两个必要前提（不做就起不来）

GPU Pod 在这台机器上必须同时带这两项：

```yaml
spec:
  hostNetwork: true          # 本地节点没有 CNI，普通 Pod 建 sandbox 会失败
  runtimeClassName: nvidia   # 默认 runc 不注入 /dev/dxg 与 NVML 库
```

RuntimeClass 需要先存在（第 2 章 device plugin 阶段建过，没有就补）：

```bash
kubectl apply -f - <<'YAML'
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata: {name: nvidia}
handler: nvidia
YAML
```

## 三、资源模型：1 卡与 2 卡

### 3.1 请求 1 卡 —— 应运行，且容器内真能看到卡

```bash
kubectl apply -f - <<'YAML'
apiVersion: v1
kind: Pod
metadata: {name: gpu-1card, namespace: ai}
spec:
  hostNetwork: true
  runtimeClassName: nvidia
  restartPolicy: Never
  nodeSelector: {kubernetes.io/hostname: ai-gpu-1}
  tolerations: [{operator: Exists}]
  containers:
  - name: cuda
    image: docker.m.daocloud.io/nvidia/cuda:12.6.0-base-ubuntu24.04
    command: ["nvidia-smi","--query-gpu=name,memory.total,driver_version","--format=csv,noheader"]
    resources: {limits: {nvidia.com/gpu: 1}}
YAML

kubectl -n ai get pod gpu-1card -o wide
kubectl -n ai logs gpu-1card
```

预期：

```
STATUS      Completed      NODE ai-gpu-1
NVIDIA GeForce RTX 3090, 24576 MiB, 621.24
```

如果 `kubectl logs` 超时（本地节点宣告的是 WSL NAT 地址，云端访问不到 10250），
把输出写进 hostPath 再本地读：

```yaml
volumeMounts: [{name: out, mountPath: /out}]
volumes: [{name: out, hostPath: {path: /tmp/gpu-out, type: DirectoryOrCreate}}]
# command 末尾加：> /out/one-card.txt 2>&1
```

### 3.2 请求 2 卡 —— 应 Pending，且原因明确

```bash
kubectl apply -f - <<'YAML'
apiVersion: v1
kind: Pod
metadata: {name: gpu-2cards, namespace: ai}
spec:
  hostNetwork: true
  runtimeClassName: nvidia
  nodeSelector: {kubernetes.io/hostname: ai-gpu-1}
  tolerations: [{operator: Exists}]
  containers:
  - name: cuda
    image: docker.m.daocloud.io/nvidia/cuda:12.6.0-base-ubuntu24.04
    command: ["sleep","60"]
    resources: {limits: {nvidia.com/gpu: 2}}
YAML

kubectl -n ai describe pod gpu-2cards | grep -A3 Events
```

预期（这就是"资源不足"的正确长相）：

```
FailedScheduling: 0/2 nodes are available:
  1 Insufficient nvidia.com/gpu,
  1 node(s) didn't match Pod's node affinity/selector.
```

**注意与 OOM 的区别**：Pending + Insufficient 是调度器根本没给；OOMKilled 是给了但用超了。

## 四、ResourceQuota：部门抢卡

```bash
kubectl create ns team-a
kubectl apply -f - <<'YAML'
apiVersion: v1
kind: ResourceQuota
metadata: {name: gpu-quota, namespace: team-a}
spec:
  hard:
    requests.nvidia.com/gpu: "1"
    limits.nvidia.com/gpu: "1"
YAML

# 第一个 Pod：配额内，应创建成功
kubectl -n team-a apply -f - <<'YAML'
apiVersion: v1
kind: Pod
metadata: {name: quota-pod-1}
spec:
  hostNetwork: true
  runtimeClassName: nvidia
  restartPolicy: Never
  nodeSelector: {kubernetes.io/hostname: ai-gpu-1}
  tolerations: [{operator: Exists}]
  containers:
  - name: cuda
    image: docker.m.daocloud.io/nvidia/cuda:12.6.0-base-ubuntu24.04
    command: ["sleep","900"]
    resources: {limits: {nvidia.com/gpu: 1}}
YAML

# 第二个 Pod：超配额，应被 API Server 拒绝
kubectl -n team-a apply -f -   # 同上，改名为 quota-pod-2
```

预期：

```
pods "quota-pod-2" is forbidden: exceeded quota: gpu-quota,
  requested: requests.nvidia.com/gpu=1,
  used: requests.nvidia.com/gpu=1,
  limited: requests.nvidia.com/gpu=1
```

这是 **Forbidden**，比 Pending 更早一步——连对象都不让建。

## 五、PriorityClass：抢占

```bash
kubectl apply -f - <<'YAML'
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata: {name: ai-low}
value: 100
---
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata: {name: ai-high}
value: 10000
YAML

# 1. 低优先级占住唯一的卡
kubectl -n ai apply -f - <<'YAML'
apiVersion: v1
kind: Pod
metadata: {name: low-pri, labels: {exp: exp2}}
spec:
  hostNetwork: true
  runtimeClassName: nvidia
  priorityClassName: ai-low
  terminationGracePeriodSeconds: 0
  nodeSelector: {kubernetes.io/hostname: ai-gpu-1}
  tolerations: [{operator: Exists}]
  containers:
  - name: cuda
    image: docker.m.daocloud.io/nvidia/cuda:12.6.0-base-ubuntu24.04
    command: ["sleep","900"]
    resources: {limits: {nvidia.com/gpu: 1}}
YAML

# 2. 高优先级来了，应触发抢占
#    （复制上面，改 name: high-pri、priorityClassName: ai-high）
```

等 15 秒后观察：

```bash
kubectl -n ai get pods -l exp=exp2 -o wide
kubectl -n ai get events --sort-by=.lastTimestamp | grep -iE 'preempt|low-pri'
```

预期：

```
high-pri   1/1  Running  ai-gpu-1
（low-pri 已消失）

FailedScheduling: ... preemption: found a potential placement for pod
                  on node ai-gpu-1, preempting 1 victims
Preempted: Preempted by pod <uid> on node ai-gpu-1
Killing:   Stopping container cuda
```

## 六、断网：NotReady 与恢复时序

只切断 kubelet → API Server 的 6443，保留 ssh 以免影响操作：

```bash
sudo iptables -I OUTPUT -d 47.238.160.73 -p tcp --dport 6443 -j DROP

# 每 10 秒看一次
for i in $(seq 1 14); do
  sleep 10
  kubectl get node ai-gpu-1 -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}{" "}{.status.conditions[?(@.type=="Ready")].reason}{"\n"}'
done

sudo iptables -D OUTPUT -d 47.238.160.73 -p tcp --dport 6443 -j DROP
```

实测时序：

```
T0       切断
+10..40s ready=True  KubeletReady
+50s     ready=Unknown  NodeStatusUnknown     ← NotReady
（此时 Pod 仍 Running，hostNetwork 不依赖 kubelet 通信）

恢复后 +10s Unknown，+20s True                ← 回 Ready
```

**失联 40 秒以上判定 NotReady（node-monitor-grace-period），恢复后 20 秒内回 Ready。**

## 七、time-slicing：假共享的代价

> 这一步会让两个 vLLM 同时抢一张卡，显存会逼近物理上限。
> 必须先腾卡（第一节），且看到显存 > 23G 就立刻停，不要等 OOM。

### 7.1 配置 replicas=4

```bash
kubectl -n kube-system create configmap nvidia-device-plugin-config --from-literal=config.yaml='
version: v1
sharing:
  timeSlicing:
    resources:
    - name: nvidia.com/gpu
      replicas: 4'

kubectl -n kube-system patch ds nvidia-device-plugin-daemonset --type=json -p='[
{"op":"add","path":"/spec/template/spec/containers/0/args","value":["--config-file=/config/config.yaml"]},
{"op":"add","path":"/spec/template/spec/containers/0/volumeMounts/-","value":{"name":"dp-config","mountPath":"/config"}},
{"op":"add","path":"/spec/template/spec/volumes/-","value":{"name":"dp-config","configMap":{"name":"nvidia-device-plugin-config"}}}
]'

kubectl get node ai-gpu-1 -o jsonpath='{.status.allocatable.nvidia\.com/gpu}{"\n"}'   # 应为 4
```

### 7.2 两个 Pod 各声明 1 卡

复制第 3 章 3.5 的 vLLM 命令，改成两个 Pod，端口分别 8001/8002，
`--gpu-memory-utilization 0.70`，都声明 `nvidia.com/gpu: 1`。

实测结果：

```
vllm-a  140 秒就绪，显存 17166 MiB
vllm-b  也被调度到同一张卡，90 秒内 Running
两个都 1/1 Running、都声明 1 卡、都落在 ai-gpu-1

显存曲线  17167 → 17511 → 23246 → 23526 → 24185（98%）
```

**没有出现 OOMKilled**，两个进程各自拿到更小份额勉强共存，代价是整卡被吃满。
结论：**time-slicing 是超卖，不是分享**。真实集群里四个人都声明 1 卡，
不是"每人 1/4"，而是"同时加载时集体逼近上限，谁先崩看运气"。

### 7.3 回滚（必须做，否则 GPU 资源永远显示 4）

```bash
# 删掉两个 Pod
kubectl -n ai delete pod vllm-a vllm-b --force --grace-period=0

# 精确移除 time-slicing 配置
kubectl -n kube-system get ds nvidia-device-plugin-daemonset -o json | python3 -c "
import json,sys
d=json.load(sys.stdin)
c=d['spec']['template']['spec']['containers'][0]
c.pop('args',None)
c['volumeMounts']=[v for v in c.get('volumeMounts',[]) if v['name']!='dp-config']
d['spec']['template']['spec']['volumes']=[v for v in d['spec']['template']['spec'].get('volumes',[]) if v['name']!='dp-config']
json.dump(d,open('/tmp/dp.json','w'))"
kubectl replace -f /tmp/dp.json
kubectl -n kube-system delete configmap nvidia-device-plugin-config

kubectl get node ai-gpu-1 -o jsonpath='{.status.allocatable.nvidia\.com/gpu}{"\n"}'   # 回到 1
```
