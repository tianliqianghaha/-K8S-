# 01 · 第 1 章 本地 GPU 节点

> 本章目标：把 Windows 这台机器变成「容器里能用 GPU 的 Linux 节点」。
> 三道闸门全过，才允许它去 join 云上集群。
> 前置条件：Windows 10 19045+、BIOS 已开 VT-x/SLAT、C 盘 ≥ 60G 可用、RTX 3090 驱动 ≥ 570。

---

## 一、动手前先确认三件事（不确认会白折腾半天）

```powershell
# 1. 虚拟化是否真的开着
Get-ComputerInfo -Property HyperVRequirementVirtualizationFirmwareEnabled, HypervisorPresent

# 2. 驱动版本与 GPU
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv

# 3. 磁盘可用空间
Get-Volume | Where-Object DriveLetter | Select-Object DriveLetter,@{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}}
```

预期：

```
HypervisorPresent                     : True（若为 False，先去 BIOS 开虚拟化）
NVIDIA GeForce RTX 3090, 621.24, 24576 MiB
C 盘至少 60G 可用（WSL 虚拟磁盘 + 模型 + 镜像）
```

驱动低于 570 建议先升级。**vLLM 新版本要求 CUDA 12.8+，560 驱动会直接报
"The NVIDIA driver on your system is too old"**，这一步省不掉。

---

## 二、打开两个 Windows 功能（管理员 PowerShell）

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

# 关掉快速启动，否则"重启"不会真正执行 DISM 收尾
powercfg /h off
bcdedit /set hypervisorlaunchtype auto

# 必须完整重启（不是关机再开）
shutdown /r /t 0
```

重启后验证：

```powershell
Get-ComputerInfo -Property HypervisorPresent      # 必须是 True
```

## 三、安装 WSL 平台（走镜像，不走 Store）

国内 Store 不提供 WSL 平台包，`wsl --install` 又要读 GitHub 上的发行版清单，两条路都不通。
正确做法是下 msixbundle 用镜像代理，再用管理员权限注册。

```powershell
mkdir C:\WSL -Force
cd C:\Users\$env:USERNAME\AppData\Local\Temp

# 通过镜像代理下载（ghfast.top 实测可用，680MB 约 6 分钟）
curl.exe -L -o Microsoft.WSL_3.0.5.0.msixbundle `
  "https://ghfast.top/https://github.com/microsoft/WSL/releases/download/3.0.5/Microsoft.WSL_3.0.5.0_x64_ARM64.msixbundle"

# 校验大小应在 680MB 左右
(Get-Item .\Microsoft.WSL_3.0.5.0.msixbundle).Length / 1MB
```

以**管理员**身份注册（这个包内嵌 Windows 服务，普通权限会报 0x80073D28）：

```powershell
Add-AppxPackage -Path "$env:TEMP\Microsoft.WSL_3.0.5.0.msixbundle"

# 验证
wsl --version
```

预期输出包含 `WSL 版本: 3.0.5.0`、`内核版本: 6.18.x`。

## 四、导入 Ubuntu 24.04（走 Canonical，不走 Store）

```powershell
cd C:\Users\$env:USERNAME\AppData\Local\Temp
mkdir wsl-install -Force; cd wsl-install

curl.exe -L -o noble-wsl-amd64.wsl `
  "https://cdimages.ubuntu.com/ubuntu-wsl/noble/daily-live/current/noble-wsl-amd64.wsl"

# 校验（对照同目录的 SHA256SUMS）
curl.exe -s "https://cdimages.ubuntu.com/ubuntu-wsl/noble/daily-live/current/SHA256SUMS" | Select-String "noble-wsl-amd64"
Get-FileHash .\noble-wsl-amd64.wsl -Algorithm SHA256
```

导入到 C 盘（`C:\WSL\Ubuntu-24.04`）：

```powershell
wsl --set-default-version 2
wsl --import Ubuntu-24.04 C:\WSL\Ubuntu-24.04 .\noble-wsl-amd64.wsl

wsl --list --verbose
```

预期：

```
  NAME            STATE           VERSION
* Ubuntu-24.04    Stopped         2
```

## 五、基础配置（内存、systemd、用户、软件源）

### 5.1 内存与 swap（`C:\Users\<你>\.wslconfig`）

```ini
[wsl2]
memory=11GB
processors=8
swap=8GB
swapFile=C:\\WSL\\swap.vhdx
localhostForwarding=true
vmIdleTimeout=86400000

[experimental]
autoMemoryReclaim=gradual
```

`vmIdleTimeout` 用于让虚拟机在客户端断开后仍保持运行；但注意它**不足以保证发行版不被终止**，
真正可靠的是第 5.4 节的常驻客户端。

### 5.2 建日常用户 + 换源 + 开 systemd

```powershell
# 以 root 进一次，跑仓库里的 06_setup-user.sh
wsl -d Ubuntu-24.04 -u root --cd /mnt/d/AI算力池实践/1.0/scripts/local -- bash 06_setup-user.sh

# 让 systemd 接管
wsl --shutdown
Start-Sleep 12
wsl -d Ubuntu-24.04 -u k8s -- bash -lc "systemctl is-system-running; stat -fc %T /sys/fs/cgroup"
```

预期：`running`（或 `degraded`）、`cgroup2fs`。

### 5.3 三道闸门之一：systemd 可用

```powershell
wsl -d Ubuntu-24.04 -u k8s -- bash -lc "id -un; nproc; free -g | head -2"
```

预期：`k8s` / `8` / 约 10G 可用。

### 5.4 让发行版常驻（关键，不做则服务会被反复终止）

WSL 会在最后一个客户端断开后终止发行版，systemd 随之停掉所有 unit。
用一个 24 小时不退出的客户端保持连接：

```powershell
schtasks /create /tn "WSL-KeepAlive" /sc minute /mo 1 `
  /tr "C:\Windows\System32\wsl.exe -d Ubuntu-24.04 -u root --exec sleep 86400" /f
schtasks /run /tn "WSL-KeepAlive"

wsl --list --running
```

预期：`Ubuntu-24.04` 处于 running。第一个实例会跑 24 小时，之后每分钟的触发因"实例未结束"被自动跳过。

## 六、GPU 工具链（容器内能看到卡）

```powershell
wsl -d Ubuntu-24.04 -u k8s --cd /mnt/d/AI算力池实践/1.0/scripts/local -- bash 02_wsl-init.sh
```

这个脚本做四件事，逐条可单独执行：

```bash
# 1. NVIDIA 容器工具链
sudo nvidia-ctk runtime configure --runtime=containerd
sudo sed -i 's/^no-cgroups.*/no-cgroups = true/' /etc/nvidia-container-runtime/config.toml

# 2. containerd 注册 nvidia runtime
#    注意：containerd 2.x 的 CRI 路径是 io.containerd.cri.v1.runtime，
#    nvidia-ctk 1.20 会写错位置，必须手工补这一段
sudo tee -a /etc/containerd/config.toml <<'EOF'
        [plugins."io.containerd.cri.v1.runtime".containerd.runtimes.nvidia]
          runtime_type = "io.containerd.runc.v2"
          [plugins."io.containerd.cri.v1.runtime".containerd.runtimes.nvidia.options]
            BinaryName = "/usr/bin/nvidia-container-runtime"
            SystemdCgroup = true
EOF
sudo systemctl restart containerd

# 3. kubelet / kubeadm（锁版本）
sudo apt-mark hold kubelet kubeadm kubectl

# 4. 镜像加速（certs.d 方式，不要用 config.toml 的 mirrors 段）
sudo mkdir -p /etc/containerd/certs.d/docker.io
sudo tee /etc/containerd/certs.d/docker.io/hosts.toml <<'EOF'
server = "https://docker.io"
[host."https://docker.m.daocloud.io"]
  capabilities = ["pull", "resolve"]
EOF
```

## 七、验收：三道闸门

```powershell
# 闸门①  systemd
wsl -d Ubuntu-24.04 -u k8s -- bash -lc "systemctl is-system-running; stat -fc %T /sys/fs/cgroup"

# 闸门②  宿主 GPU 能透进 WSL
wsl -d Ubuntu-24.04 -u k8s -- bash -lc "nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader"

# 闸门③  容器里能看到 GPU
wsl -d Ubuntu-24.04 -u k8s -- bash -lc "sudo ctr run --rm --runtime io.containerd.runc.v2 --runc-binary /usr/bin/nvidia-container-runtime docker.m.daocloud.io/nvidia/cuda:12.6.0-base-ubuntu24.04 t1 nvidia-smi"
```

三项预期：

```
① running · cgroup2fs · 8 vCPU / 10G
② NVIDIA GeForce RTX 3090, 24576 MiB, 621.24
③ 容器内同样输出 RTX 3090 / 24576 MiB
```

三关全过，这个节点才有资格进入第 2 章。
