# 00 · 总览与复现路线

> 这套东西是什么：把自己家里一张 RTX 3090 变成云上可调度、可计量、可排队的推理算力池。
> 云上只放控制面和治理件（4C8G 抢占实例，约 0.22 元/时），真正的算力在本机。
> 全套实测跑通时间：2026-11-22 15:00 — 21:30。
>
> **当前状态：环境已释放。** 云端实例已删除（地域内 0 台），本地五个服务已停并取消自启，
> WSL 已关闭。要重新启用照 `07_速查卡.md` 第八节做。本手册是完整的重建依据。

## 一、三个实验分别证明什么

```
实验一  应用层反连        证明「云调度、本执行」这条链每一环都通
        客户端 → HTTPS 入口 → 云端 gateway（鉴权/限流/队列）
        → WebSocket 出站长连接 → 本地 Agent → vLLM → 逐字回流
        验收：首字 < 1.5s、并发有拐点、gateway 重启不丢任务、断网 30s 能恢复

实验二  内核层注册        证明「调度是真的」，资源语义由 K8S 裁决
        同一张卡：要 1 卡能跑、要 2 卡就 Pending、配额能卡死、抢占能踢人
        验收：Capacity 有 nvidia.com/gpu=1、GPU Pod 落本地、抢占事件可见、断网有明确时序

实验三  治理平面          证明「能跑」变成「能管」
        Kueue 排队 + KEDA 按队列扩 + Grafana 大盘 + chaos 延迟注入
        + Argo 金丝雀自动回滚 + OpenCost 成本分摊
        验收：排队与配额可见、四个关键数字一张图、失败版本自动回退
        达成度：七项全过，OpenCost 部署通过但数值没算出来（第 5 章第 7 节有说明）
```

两次接入方式（应用层反连 vs 内核层注册）的并存，本身就是这个项目最有价值的对比：
**反连负责把任务送到卡上，K8S 负责裁决谁有资格用卡。**

## 五、成本账（实测）

```
云上 4C8G 抢占          0.075 元/时
100G ESSD entry         约 0.14 元/时
合计                    约 0.22 元/时 ≈ 5 元/天

三个实验合计约 6.5 小时，云上花费约 1.5 元
本地电费 3090 满载 350W × 6.5h ≈ 1.3 元
全程 3 元以内
```

省下来的关键：不做控制面 HA（省 2 台）、不装 Longhorn（省每节点 150G 盘）。
这两笔在通用 K8S 平台里占成本六成以上，但对"验证 AI 链路"零贡献。

## 六、这套环境的三个硬约束（不要试图绕过，只能适配）

```
约束一  本机只有 16G 内存、24G 显存
        对策  模型用 7B AWQ 4bit（权重 4.5G），gpu-memory-utilization 0.72
              WSL 分配 11G，宿主留 5G

约束二  Windows 10 + WSL2，不是裸金属 Linux
        对策  GPU Pod 一律 hostNetwork + runtimeClassName nvidia
              本地节点不装 CNI，跨公网靠反连而不是 Pod 网络
              推理服务放在 systemd 而不是 K8S（kubelet 在 WSL 上会因 socket 丢失反复重启）

约束三  云端是最低档 100G ESSD，IOPS 有限
        对策  监控抓取间隔 120s，只留必要指标
              etcd 对 fsync 极敏感，任何"大写入"都会直接把控制面拖死
```
