# 03 · 第 3 章 实验一：应用层反连（最小闭环）

> 本章目标：用「云端 gateway + 本地 Agent + WebSocket 反连」把请求链路接起来，
> 拿到首字延迟与并发拐点的基线，并证明重启/断网时任务不丢。
> 前置条件：第 2 章两个节点 Ready、`nvidia.com/gpu=1` 已上报。
> 本章刻意不碰 kubelet 调度，先把变量减到最少。

---

## 一、这条链路

```
客户端 curl
  │  HTTPS + Bearer API Key
  ▼
Envoy Gateway（NodePort 31154，自签 TLS）
  ▼
云端 ai-gateway（FastAPI / uvicorn）
  ├─ 鉴权      Authorization: Bearer / X-API-Key
  ├─ 限流      每 key 每分钟 60 次滑动窗口，超限 429 + Retry-After
  ├─ 幂等      Idempotency-Key 命中已完成任务直接回缓存
  ├─ 任务队列  queued → streaming → done
  └─ 派发      通过 /agent 的 WebSocket 推任务
  │  WSS 出站长连接（本地主动连云端，所以 NAT 后面也能被派活）
  ▼
本地 ai-agent（systemd 托管）
  ├─ 收任务 → 调本地 vLLM 流式接口
  ├─ 增量回传 → 每吐一个 token 发一个 chunk
  ├─ 幂等     → 已完成的 task_id 直接回 done
  └─ 不丢任务 → 断线保留 inflight，重连后 resume
  ▼
本地 vLLM v0.34.0（Qwen2.5-7B-Instruct-AWQ）
```

为什么反连：WSL 在本机 NAT 后面，没有固定可达地址。边缘节点主动连云端是标准做法，
这也是与第 4 章「内核层注册」对照的关键差异。

## 二、源码

```
scripts/app/gateway/main.py    374 行   云端 gateway
scripts/app/agent/main.py      179 行   本地 Agent
```

gateway 的核心结构：

```python
class Task:  id / payload / idem / chunks / status / usage / waiters
dispatch()      从 agents 里挑一个 WS，send_json 推任务；无 Agent 时保持 queued（不返回 503）
sse()           轮询 task.chunks 转成 SSE，支持超时与 error 终止
/agent WS       收 chunk / done / error / resume / ping，断连时把未产出 chunk 的任务退回 queued
/metrics        agents_connected / queue_depth / streaming_tasks / 各类计数器
```

agent 的核心结构：

```python
重连退避   1s → 2s → 4s → 8s → 10s 封顶
并发上限   semaphore MAX_CONCURRENT=8
resume     重连时把未完成任务连 buffer 一起上报
SSL        自签证书：check_hostname=False + verify_mode=CERT_NONE
```

## 三、部署步骤

### 3.1 装 Envoy Gateway

```bash
helm install eg oci://docker.io/envoyproxy/gateway-helm --version v1.10.0 \
  -n envoy-gateway-system --create-namespace --wait --timeout 6m

# 必须手动建 GatewayClass（1.10 不会自动创建）
kubectl apply -f - <<'YAML'
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: eg
spec:
  controllerName: gateway.envoyproxy.io/gatewayclass-controller
YAML

kubectl get gatewayclass        # ACCEPTED 应为 True
```

### 3.2 自签证书

实验环境没有域名，用自签，SAN 里同时写公网和私网 IP：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
  -keyout /tmp/tls.key -out /tmp/tls.crt \
  -subj "/CN=47.238.160.73" \
  -addext "subjectAltName=IP:47.238.160.73,IP:172.23.163.98"

kubectl create ns ai
kubectl -n ai create secret tls ai-tls --cert=/tmp/tls.crt --key=/tmp/tls.key
```

### 3.3 gateway 应用

```bash
kubectl -n ai create configmap gateway-code \
  --from-file=main.py=scripts/app/gateway/main.py

kubectl apply -f - <<'YAML'
apiVersion: apps/v1
kind: Deployment
metadata: {name: ai-gateway, namespace: ai}
spec:
  replicas: 1
  selector: {matchLabels: {app: ai-gateway}}
  template:
    metadata: {labels: {app: ai-gateway}}
    spec:
      containers:
      - name: gateway
        image: docker.io/library/python:3.12-slim
        workingDir: /app
        command: ["/bin/sh","-c"]
        args:
        - pip install --no-cache-dir -q -i https://mirrors.aliyun.com/pypi/simple/ fastapi 'uvicorn[standard]' && exec uvicorn main:app --host 0.0.0.0 --port 8080 --ws websockets
        ports: [{containerPort: 8080}]
        env:
        - {name: API_KEYS, value: "sk-ai-pool-2026"}
        - {name: RATE_LIMIT, value: "60"}
        - {name: TASK_TIMEOUT, value: "300"}
        volumeMounts: [{name: code, mountPath: /app}]
        readinessProbe:
          httpGet: {path: /health, port: 8080}
          initialDelaySeconds: 30
          periodSeconds: 5
      volumes: [{name: code, configMap: {name: gateway-code}}]
---
apiVersion: v1
kind: Service
metadata: {name: ai-gateway, namespace: ai}
spec:
  selector: {app: ai-gateway}
  ports: [{name: http, port: 80, targetPort: 8080}]
YAML
```

### 3.4 入口（EnvoyProxy + Gateway + HTTPRoute）

```bash
kubectl apply -f - <<'YAML'
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: EnvoyProxy
metadata: {name: nodeport, namespace: ai}
spec:
  provider:
    type: Kubernetes
    kubernetes:
      envoyService: {type: NodePort}
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata: {name: ai-gateway, namespace: ai}
spec:
  gatewayClassName: eg
  infrastructure:
    parametersRef: {group: gateway.envoyproxy.io, kind: EnvoyProxy, name: nodeport}
  listeners:
  - name: https
    protocol: HTTPS
    port: 443
    tls: {mode: Terminate, certificateRefs: [{kind: Secret, name: ai-tls}]}
    allowedRoutes: {namespaces: {from: Same}}
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: {name: ai-gateway-route, namespace: ai}
spec:
  parentRefs: [{name: ai-gateway}]
  rules:
  - matches: [{path: {type: PathPrefix, value: /}}]
    backendRefs: [{name: ai-gateway, port: 80}]
YAML

# 查实际 NodePort
kubectl -n envoy-gateway-system get svc | grep envoy
```

预期：`Programmed=True`，NodePort 形如 `443:31154`。

### 3.5 本地 vLLM（systemd 托管）

```bash
sudo tee /etc/systemd/system/vllm.service > /dev/null <<'UNIT'
[Unit]
Description=vLLM OpenAI server (Qwen2.5-7B-AWQ)
After=containerd.service
Requires=containerd.service

[Service]
Type=simple
Restart=always
RestartSec=10
TimeoutStartSec=0
KillMode=process
LimitNOFILE=65536
ExecStartPre=-/usr/bin/ctr -n k8s.io task kill -s SIGKILL vllm-server
ExecStartPre=-/usr/bin/ctr -n k8s.io task delete -f vllm-server
ExecStartPre=-/usr/bin/ctr -n k8s.io container delete vllm-server
ExecStart=/usr/bin/ctr -n k8s.io run --rm --runtime io.containerd.runc.v2 --runc-binary /usr/bin/nvidia-container-runtime --env NVIDIA_VISIBLE_DEVICES=all --net-host --mount type=bind,src=/home/k8s/models,dst=/models,options=rbind:ro docker.m.daocloud.io/vllm/vllm-openai:latest vllm-server python3 -m vllm.entrypoints.openai.api_server --model /models/Qwen2.5-7B-Instruct-AWQ --served-model-name qwen --host 0.0.0.0 --port 8000 --gpu-memory-utilization 0.72 --max-model-len 8192 --enable-prefix-caching --enforce-eager
ExecStop=/usr/bin/ctr -n k8s.io task kill -s SIGTERM vllm-server

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload && sudo systemctl enable --now vllm
```

关键参数解释：

```
--gpu-memory-utilization 0.72   WSL 下 0.80 会 OOM，0.72 是安全线
--enforce-eager                 不捕获 CUDA graph，降低峰值显存
--enable-prefix-caching         KV 复用，长对话省钱
```

启动约 150 秒，验证：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/health     # 200
nvidia-smi --query-gpu=memory.used --format=csv,noheader                  # 约 17.7G
```

### 3.6 本地 Agent（systemd，不用 Pod）

```bash
sudo apt-get install -y -qq python3-pip python3-venv
mkdir -p /home/k8s/agent && cp scripts/app/agent/main.py /home/k8s/agent/
python3 -m venv /home/k8s/agent/venv
/home/k8s/agent/venv/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple/ aiohttp websockets

sudo tee /etc/systemd/system/ai-agent.service > /dev/null <<'UNIT'
[Unit]
Description=AI pool edge agent (reverse WebSocket)
After=network-online.target vllm.service
Wants=network-online.target

[Service]
Type=simple
User=k8s
WorkingDirectory=/home/k8s/agent
Environment=GATEWAY_WS=wss://47.238.160.73:31154/agent
Environment=VLLM_URL=http://127.0.0.1:8000/v1/chat/completions
Environment=AGENT_NAME=ai-gpu-1
Environment=MAX_CONCURRENT=8
ExecStart=/home/k8s/agent/venv/bin/python -u /home/k8s/agent/main.py
Restart=always
RestartSec=5
TimeoutStartSec=0
UNIT

sudo systemctl daemon-reload && sudo systemctl enable --now ai-agent
journalctl -u ai-agent -n 10 --no-pager      # 应看到 connected / welcome
```

验证 Agent 已连上：

```bash
curl -sk https://47.238.160.73:31154/health
# {"status":"ok","agents":1,...}
```

## 四、四道闸门验收

### 闸门① 首字延迟 < 1.5 秒

```bash
for i in 1 2 3 4 5; do
  curl -skN -o /dev/null -X POST https://47.238.160.73:31154/v1/chat/completions \
    -H "Authorization: Bearer sk-ai-pool-2026" -H "Content-Type: application/json" \
    -d '{"model":"qwen","messages":[{"role":"user","content":"用一句话说说今天天气适合做什么"}],"max_tokens":50,"stream":true}' \
    -w "  第${i}次 TTFT=%{time_starttransfer}s TOTAL=%{time_total}s\n"
done
```

实测：`TTFT 0.116 / 0.116 / 0.120 / 0.129 / 0.144`，平均 0.125s，余量 12 倍。

### 闸门② 并发曲线出现拐点

```bash
# 用 scripts/app/bench/gw_bench.py，或直接写 python 并发脚本
python3 gw_bench.py
```

实测：

```
并发  总耗时  平均延迟  P95     完成/失败
  1   0.43s   0.43s    0.43s   1/0
  4   0.37s   0.35s    0.37s   4/0
  8   0.47s   0.45s    0.46s   8/0
 16   3.05s   1.46s    2.81s   16/0
```

**拐点在 8 与 16 之间**，8 是这台卡的容量上限，第 5 章的排队设计就以此为基准。

### 闸门③ gateway 重启，Agent 自动重连

```bash
kubectl -n ai rollout restart deploy/ai-gateway

# 观察 Agent 日志
journalctl -u ai-agent -f | grep -E "disconnected|connecting|welcome"
```

实测：

```
[20:02:53] disconnected: ConnectionClosedError: received 1012 (service restart); retry in 1s
[20:02:54] connecting wss://...:31154/agent
[20:02:54] connected / welcome agent_id=agent-6bfbd3b9
```

1 秒内重连，重启后请求照常 200。

### 闸门④ 断网 30 秒，积压任务继续

```bash
# 断到云端的出口
sudo iptables -I OUTPUT -d 47.238.160.73 -j DROP

# 断网期间发 3 个请求（后台）
for i in 1 2 3; do
  curl -sk --max-time 200 -X POST https://47.238.160.73:31154/v1/chat/completions \
    -H "Authorization: Bearer sk-ai-pool-2026" -H "Content-Type: application/json" \
    -d "{\"model\":\"qwen\",\"messages\":[{\"role\":\"user\",\"content\":\"断网测试${i}\"}],\"max_tokens\":40}" \
    -o /tmp/net_$i.json -w "%{http_code}" > /tmp/net_$i.code &
done

sleep 30
sudo iptables -D OUTPUT -d 47.238.160.73 -j DROP
wait
cat /tmp/net_1.code /tmp/net_2.code /tmp/net_3.code      # 全部 200
```

实测：3 个请求全部 200 返回"好的"，Agent 在恢复后 1 秒重连。
