## 二、三个硬约束与对策

### 约束一 · 内存只有 15.9 GB

```
WSL2 默认抢走宿主机 50% = 8GB，不够用；给太多宿主机会卡死。
本方案定为：WSL 11GB / 宿主 5GB / swap 8GB 落 D 盘

7B FP16 权重 = 15GB
  加载峰值 RAM 会撞 swap，vLLM 大概率启动失败或被 OOMKilled
  这不是玄学，是 16GB 物理内存装不下 15GB 权重的加载缓冲

对策：实验一改用 7B AWQ 4bit
  权重      约 4.5 GB
  显存占用  约 6–7 GB
  RAM 峰值  约 3–4 GB
  省下的 17GB 显存全部给 KV cache → 上下文能开到 32K
```

**这不是缩水。** 4bit 量化在生产里就是主流做法，而且它让你第一次实验的
变因更少：先证明链路通，再谈精度。FP16 留到环境稳了之后单独对照。

### 约束二 · Windows 10 而不是 Windows 11

```
影响   WSL2 的 mirrored 网络模式不可用（那是 Win11 22H2+ 的功能）
       WSL2 在 Win10 上是 NAT 网络，内部 IP 每次重启都变

对策   Tailscale 装进 WSL2 内部（WSL2 内核有 TUN 支持）
       kubelet 的 --node-ip 必须绑 Tailscale 的 100.x 地址，不能绑 eth0
       Tailscale IP 是固定的，重启不变 —— 这一点比 eth0 可靠
```

### 约束三 · wsl.exe 被安全策略拦截

```
现象   我这边的沙箱有程序黑名单，wsl.exe 直接被拒，且无法绕过
影响   只能拦我，拦不到你自己开的终端
分工   三个脚本我写、输出我判读；凡是带 wsl 命令的那一步，由你执行
```

如果想让后续动作更顺，可以在 `安全中心 → 命令安全 → 程序黑名单`
里移除 `wsl.exe`，但它不是必需的——你自己跑一样。

## 三、执行顺序（一次重启，四个动作）

```
① 管理员 PowerShell
   cd D:\AI算力池实践\1.0\scripts\local
   powershell -ExecutionPolicy Bypass -File .\00_enable-wsl2.ps1
   → 启用两个 Windows 功能，末尾提示重启

② 重启电脑
   Restart-Computer

③ 普通 PowerShell（重启后）
   cd D:\AI算力池实践\1.0\scripts\local
   powershell -ExecutionPolicy Bypass -File .\01_install-wsl.ps1
   → 装 WSL2 + Ubuntu 24.04，写入 .wslconfig

④ 让 systemd 生效（关键，容易漏）
   wsl -d Ubuntu-24.04                    # 首次会让你设用户名密码（建议 k8s）
   # 进去后先退出，再执行：
   wsl --shutdown

⑤ 回到 WSL，跑初始化
   wsl -d Ubuntu-24.04
   cd /mnt/d/AI算力池实践/1.0/scripts/local
   bash 02_wsl-init.sh
   → 装 GPU 工具链、containerd、kubelet、Tailscale
   → 若它提示「systemd 配置已写入，请 wsl --shutdown」，照做再来一遍
```

## 四、三道闸门（全过才算环境就绪）

```
闸门①  WSL2 能跑 systemd
        systemctl is-system-running        → running 或 degraded
        不过的表现：containerd/kubelet 装了但起不来

闸门②  宿主 GPU 能透进来
        nvidia-smi                          → 看到 RTX 3090 / 24576MiB
        不过的表现：报 "No devices were found" 或 "Failed to initialize NVML"

闸门③  容器里能看到 GPU
        sudo nerdctl run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
        不过的表现：容器起来但容器内 nvidia-smi 报错 → no-cgroups 没设 true

三关过后才轮到第四件事：加入云上集群（实验一 03 章）。
```

## 五、提前写好的退路

```
① WSL2 里 nvidia-smi 看不到卡
   先查 Windows 端：驱动 560+ 、没有禁用 GPU、没有独占模式占用
   WSL 的 GPU 通道由 Windows 驱动提供，所以"Windows 能跑、WSL 不能"一定是通道问题，
   不是装 CUDA 的问题 —— 别在 WSL 里反复装 CUDA toolkit，那是白费

② 容器内看不到 GPU
   99% 是 /etc/nvidia-container-runtime/config.toml 里 no-cgroups 还是 false
   WSL2 的 cgroup 不给 GPU 用，必须设 true

③ Tailscale 起不来（tun 设备）
   退 SSH 反向隧道：ssh -R 10250:localhost:10250 user@云机
   或 frp。两者都能让云端访问到本地 kubelet，只是不如 Tailscale 方便

④ kubelet 报 bridge-nf-call-iptables 不存在
   WSL2 内核可能没编 br_netfilter。因为本地节点不跑 CNI、不跑 kube-proxy，
   这个检查可以绕过：kubelet 启动参数加 --fail-swap-on=false 之外，
   必要时用 --feature-gates 或直接忽略该告警

⑤ WSL 内存不够、模型加载失败
   改 .wslconfig 的 memory 到 12GB，swap 提到 12GB（慢但能过）
   或者模型降到 4B
```

### 7.3 踩过的八个坑（按发生顺序）

```
① 快速启动让"重启"假生效
   现象  InstallState=1 但 HypervisorPresent=False，uptime 仍 19 小时
   根因  关机再开机恢复内核会话，DISM 收尾没执行，hypervisor 没拉起
   解    powercfg /h off + bcdedit /set hypervisorlaunchtype auto + shutdown /r

② GitHub 全断，WSL 装不上
   现象  winget 0x80072efd；wsl --install 无法取 DistributionInfo.json
   根因  github.com / raw.githubusercontent.com 不可达
   解    镜像代理 ghfast.top 下 msixbundle；或 cdimages.ubuntu.com 下 .wsl 发行版

③ msixbundle 装不进去
   现象  0x80073D28 需要管理员
   根因  包内嵌 Windows 服务，注册打包服务要管理员令牌
   解    管理员 PowerShell 跑 Add-AppxPackage

④ swap 文件路径不存在
   现象  wsl: 未能在 C:\WSL\swap.vhdx 中创建交换磁盘
   根因  .wslconfig 指的目录没建
   解    先 New-Item C:\WSL

⑤ containerd 2.x 配置路径变了，nvidia-ctk 静默失败
   现象  nvidia-ctk 报成功，但 config.toml 里搜不到 nvidia
   根因  CRI 配置从 io.containerd.grpc.v1.cri 挪到 io.containerd.cri.v1.runtime
   解    手动加 [plugins."io.containerd.cri.v1.runtime".containerd.runtimes.nvidia]
         BinaryName = /usr/bin/nvidia-container-runtime

⑥ PowerShell 5.1 读 UTF-8 无 BOM 脚本按 GBK 解析
   现象  报"缺少右括号"，看起来像语法错误
   解    文件加 UTF-8 BOM

⑦ bat 里 chcp 65001 + GBK 编码内容 = 命令行被撕碎
   现象  'ocal"' / 'cho' 不是内部或外部命令
   解    bat 全 ASCII，路径用 %~dp0，不写死中文绝对路径

⑧ WSL 的输出经 PowerShell 管道会丢
   现象  tail -30 无输出、sudo 后的行消失
   解    全部重定向到 /mnt/c/.../xxx.log，再用 Get-Content 读

⑨ 多行字符串当参数传给 wsl bash -lc 会被截断
   现象  syntax error: unexpected end of file
   解    写成 .sh 文件，wsl 执行文件路径
```

### 7.4 一条可复用的经验

```
WSL2 节点上，跨公网这一层不是靠 CNI 解决的，是靠"这个节点不接 CNI"解决的。
所以本地这三道闸门只验到"GPU 能被容器用"，至于 Pod 网络，
从一开始就不打算让它参与 —— 后面 join 集群时用 hostNetwork。
```
