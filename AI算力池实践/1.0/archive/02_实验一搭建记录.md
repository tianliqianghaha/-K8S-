## 三、这一轮踩的九个坑

```
① 阿里云 hairpin NAT
   现象 实例内部访问自己的公网 IP 6443 超时，kubectl 全挂
   根因 公网 IP 是 NAT 映射，回环不通
   解   内部操作 kubeconfig 用私网 172.23.163.98，本地用公网，证书 SAN 两个都有

② kubeadm 1.37 移除了 --node-labels
   现象 unknown flag: --node-labels
   解   改用 JoinConfiguration 文件，label 交给 kubectl 事后加

③ node-role.kubernetes.io/* 不在 kubelet 允许的 label 前缀里
   现象 failed to validate kubelet flags: unknown 'kubernetes.io' labels
   根因 1.37 收紧到只允许 kubelet.kubernetes.io / node.kubernetes.io 等
   解   去掉 label，只留 taint

④ containerd 2.x：config_path 与 mirrors 互斥
   现象 CRI images 插件 error，join 报 unknown service runtime.v1.RuntimeService
   根因 默认配置已有 config_path，我又追加了 registry.mirrors
   解   删 mirrors，改用 /etc/containerd/certs.d/docker.io/hosts.toml

⑤ Cilium DaemonSet 的 toleration 能容忍所有 taint
   现象 明明打了 nvidia.com/gpu taint，cilium 还是调度到 GPU 节点
   根因 DaemonSet 带 operator: Exists
   解   patch DaemonSet 加 nodeAffinity，用 kubernetes.io/hostname NotIn 排除

⑥ 无 CNI 导致节点 NotReady
   现象 NetworkReady=false reason:NetworkPluginNotReady
   解   /etc/cni/net.d/05-loopback.conf 写一个 loopback-only CNI，让 kubelet 认为网络就绪
        代价：该节点上的非 hostNetwork Pod 没有网络（我们不需要）

⑦ registry.k8s.io 在本地解析到 Google CDN，不通
   现象 拉 pause:3.10.1 超时 europe-west3-docker.pkg.dev
   解   阿里云 registry.aliyuncs.com/google_containers 拉同版本，ctr tag 成 registry.k8s.io 原名

⑧ WSL2 里 device plugin 需要 runtimeClassName
   现象 Pod Running 但 nvidia.com/gpu 不上报
   根因 默认 runc 不注入 /dev/dxg 与 NVML 库
   解   建 RuntimeClass nvidia，Pod 加 runtimeClassName: nvidia

⑨ 镜像源不代理 nvcr.io
   现象 daocloud / 1panel / rat.dev 对 nvidia/k8s-device-plugin 均 not found 或 403
   解   云端拉 nvcr.io（8.4MB/s）→ ctr export → scp 235MB（18.7s）→ 本地 ctr import
```

## 五、vLLM 为什么长时间起不来：四个真因（按发现顺序）

这一段是本次最重要的沉淀。前面所有"崩溃、显存消失、反复重试"的现象，全部由下面四个原因叠加造成，**没有一个是 vLLM 本身的问题**。

```
① ctr run 的参数位置
   现象  runc create failed: exec: "--model": executable file not found in $PATH
   原因  ctr run 的语法是  ctr run [flags] IMAGE CONTAINER_ID [COMMAND] [ARGS...]
         容器 ID 之后的第一个词被当成要执行的命令，镜像的 ENTRYPOINT 不会自动生效
   解    必须显式写全   ... vllm-openai:latest vllm-server python3 -m vllm.entrypoints.openai.api_server --model ...
   判定  这个判断是对的，但它只解释"启动即报错"，不能解释"跑起来又消失"

② WSL 会话断开即终止发行版（本次最大的坑，耗时最久）
   现象  每次命令结束 8 秒内，systemd 记 Stopping vllm.service，
         容器内 vLLM 收到 SIGTERM 打出 KeyboardInterrupt: terminated，
         显存从 20G 瞬掉到 300M。用户看到的就是"一开始测试就退出"
   原因  WSL 在最后一个 wsl.exe 客户端断开后会终止整个发行版，
         systemd 随之停掉所有 unit。这与代码、参数、驱动都无关
   验证  .wslconfig 加 vmIdleTimeout=86400000 无效，发行版仍被终止
   解    制造一个永不退出的 wsl 客户端：
           schtasks /create /tn WSL-KeepAlive2 /sc minute /mo 1
             /tr "wsl.exe -d Ubuntu-24.04 -u root --exec sleep 86400"
         第一个实例跑 24h，之后每分钟的触发因"实例未结束"被自动跳过，
         等价于一个长连接。加 /run 立即启动，实测会话断开后 uptime 持续增长、health 恒为 200
   注    AtLogOn 触发需要管理员权限（拒绝访问），minute 触发普通用户可建

③ gpu-memory-utilization 0.80 在 WSL 下是超配
   现象  RuntimeError: GPU driver error 2: out of memory，
         启动峰值冲到 24193 MiB（98%），随后 EngineCore 死掉
   原因  vLLM 按 Windows 汇报的 24576 MiB 计算配额，
         但 WSL 里 CUDA 上下文、D3D 映射、桌面显示已占掉一部分余量
   解    0.72 + --enforce-eager（不捕获 CUDA graph，峰值最低）
         最终峰值 20438，稳定 20440，留 4.1G 余量
   教训  在 WSL 上不要按总显存算比例，0.72 是这台机器的安全线

④ K8S 反复重建 Pod 导致多实例抢显存
   现象  11 个 Pod 同时存在，10 个 UnexpectedAdmissionError，
         节点心跳丢失，显存被拉到爆
   原因  device plugin 在 kubelet 抖动期间把 GPU 标成 unhealthy，
         ReplicaSet 无限重试；同时 8 个 vllm 容器残留在 ctr 里各占 20G
   解    放弃 K8S 承载推理，改 systemd + ctr 单实例；
         ExecStartPre 每次启动前强杀同名 task 与容器；
         一次性清掉 10 个残留容器定义
```

关键分界：**K8S 保留 GPU 调度能力（已证明 nvidia.com/gpu=1 上报成功），但推理服务不放在 K8S 里**。原因是 WSL2 上 kubelet 会因 `/run` 是 tmpfs、containerd socket 丢失而反复重启，每次重启都 SIGTERM 掉容器，这个循环在 WSL 上无法根治。

## 六、最终单元文件（可直接复用）

`/etc/systemd/system/vllm.service`：
```
[Unit]
Description=vLLM OpenAI server (Qwen2.5-7B-AWQ)
After=containerd.service
Requires=containerd.service

[Service]
Type=simple
Restart=always
RestartSec=10
TimeoutStartSec=0
KillMode=process
LimitNOFILE=65536
ExecStartPre=-/usr/bin/ctr -n k8s.io task kill -s SIGKILL vllm-server
ExecStartPre=-/usr/bin/ctr -n k8s.io task delete -f vllm-server
ExecStartPre=-/usr/bin/ctr -n k8s.io container delete vllm-server
ExecStart=/usr/bin/ctr -n k8s.io run --rm \
  --runtime io.containerd.runc.v2 \
  --runc-binary /usr/bin/nvidia-container-runtime \
  --rlimit nofile=65536 \
  --env NVIDIA_VISIBLE_DEVICES=all \
  --net-host \
  --mount type=bind,src=/home/k8s/models,dst=/models,options=rbind:ro \
  docker.m.daocloud.io/vllm/vllm-openai:latest vllm-server \
  python3 -m vllm.entrypoints.openai.api_server \
  --model /models/Qwen2.5-7B-Instruct-AWQ \
  --served-model-name qwen \
  --host 0.0.0.0 --port 8000 \
  --gpu-memory-utilization 0.72 \
  --max-model-len 8192 \
  --enable-prefix-caching \
  --enforce-eager
ExecStop=/usr/bin/ctr -n k8s.io task kill -s SIGTERM vllm-server

[Install]
WantedBy=multi-user.target
```

`/etc/systemd/system/vllm-tunnel.service`：
```
[Unit]
Description=Reverse SSH tunnel: local vLLM 8000 -> ai-cp-1:8000
After=network-online.target vllm.service
Wants=network-online.target

[Service]
Type=simple
Restart=always
RestartSec=10
TimeoutStartSec=0
ExecStart=/usr/bin/ssh -N -i /home/k8s/.ssh/id_ed25519 \
  -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR \
  -o ServerAliveInterval=20 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes \
  -R 8000:127.0.0.1:8000 root@47.238.160.73
```
