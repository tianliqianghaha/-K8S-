## 10.1 在干什么

两件事分开：

```
GitOps（ArgoCD）：让"集群状态"永远等于"Git 里的状态" —— 解决"谁偷偷改了线上"
渐进发布（Rollouts）：让"新版本"分批上 —— 解决"一换镜像全站炸"
```

## 10.2 敲什么

```bash
# ArgoCD
helm upgrade --install argocd argo/argo-cd -n argocd --create-namespace \
  --set server.replicas=2 --set repoServer.replicas=2 --set applicationSet.replicas=2 \
  --set configs.params."server\.insecure"=true \
  --set server.service.type=NodePort --set server.service.nodePortHttp=30080 --wait

# 仓库凭据（ArgoCD 用一个带 label 的 secret 认仓库）
kubectl -n argocd create secret generic gitea-repo \
  --from-literal=type=git \
  --from-literal=url=http://172.23.163.111:3000/gitea_admin/k8s-manifests.git \
  --from-literal=username=gitea_admin --from-literal=password='<pw>'
kubectl -n argocd label secret gitea-repo argocd.argoproj.io/secret-type=repository

# Application（app-of-apps 形态）
kubectl apply -f apps/app-of-apps.yaml
```

## 10.4 Rollout 的两种形态（注意别写错）

```yaml
# ✗ 会报错：SetCanaryScale requires TrafficRouting to be set
steps:
  - setCanaryScale: {replicas: 1}
  - pause: {duration: 40s}

# ✓ 本次可用：纯副本比例 + 暂停门禁（不需要流量管理器）
steps:
  - pause: {duration: 30s}
  - pause: {duration: 30s}
```

**判据**：`setWeight` / `setCanaryScale` 属于"按流量切"，必须有 trafficRouting；
只写 `pause` 是"按副本比例 + 人工/定时门禁"，不依赖任何流量组件。

## 10.5 判官卡：canary 按什么切

```
选项 A 按副本比例 + pause 门禁（本次）
  能做的：新旧版本同时存在，观察新版本 Pod 是否稳定
  不能做：控制"多少请求打到新版本"——Service 层面仍是轮询

选项 B Gateway API trafficRouting（argoproj-labs/gatewayAPI 插件）+ 第 3 章的 Envoy Gateway
  能做：真正按百分比导流（1% → 5% → 50%）
  代价：多一个插件 + 要装入口控制器

选项 C 服务网格（Istio/waypoint）流量切分
  能做：最细（按 header、按用户）
  代价：最重

判据：练"发布流程"用 A；练"发布策略"必须上 B。
本次：A（因为入口控制器还没装，见第 11 章与 13 章的对账）。
```

## 核心大坑（3 条）

```
现象：ArgoCD 里 Application 一直 OutOfSync，但集群里看起来正常
根因：Git 里的清单与线上有"无害差异"（比如 HPA 改了 replicas）
防：Application 里加 ignoreDifferences（/spec/replicas），别用 selfHeal 硬怼

现象：KEDA/HPA 托管副本数 + ArgoCD selfHeal → 副本数反复跳
根因：两个控制器都在管 replicas
防：HPA/KEDA 接管的 Deployment，ArgoCD 侧必须忽略 replicas

现象：Rollout 一创建就 Degraded，报 InvalidSpec
根因：用了 setCanaryScale 但没配 trafficRouting（本次真实踩到）
防：要么加 trafficRouting，要么只用 pause 步骤
```
