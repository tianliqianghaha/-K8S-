## 1.1 在干什么

把 10 台裸机推到同一个起点：**内核参数一致、运行时一致、kubeadm 版本一致**。
三样缺一样，后面就会出现"某台节点莫名 NotReady"。

## 1.2 为什么现在做

kubelet 对运行时的要求是硬性的：cgroup v2 + systemd 驱动 + 已 hold 的版本。
这三件事在 init 之后补，等于重建。

## 1.3 在哪台敲

不手敲。从本机用 SSH 并发推到 10 台（脚本 `s1/*.sh` + `s1_bootstrap.py`）。

## 1.4 敲什么（四段的顺序不能换）

```
① base.sh      关 swap / 时区 / chrony / 主机名 / hosts / 关自动更新
② kernel.sh    modules-load + sysctl + THP 关闭（独立 systemd unit，早于 kubelet）
③ runtime.sh   containerd 2.2.2 + SystemdCgroup=true + crictl
④ k8s.sh       pkgs.k8s.io/core:/stable:/v1.37 + 三件套 + apt-mark hold
```

关键三段原文（可直接照抄）：

```bash
# ② 内核
cat > /etc/modules-load.d/k8s.conf <<'EOF'
overlay
br_netfilter
nf_conntrack
EOF
cat > /etc/sysctl.d/99-kubernetes.conf <<'EOF'
net.bridge.bridge-nf-call-iptables  = 1
net.ipv4.ip_forward                 = 1
net.netfilter.nf_conntrack_max      = 1048576
fs.inotify.max_user_watches         = 524288
EOF
sysctl --system

# ③ 运行时（26.04 的包名是 containerd，不是 containerd.io）
apt-get install -y -qq containerd runc
containerd config default > /etc/containerd/config.toml
sed -i 's/^\(\s*\)SystemdCgroup = false/\1SystemdCgroup = true/' /etc/containerd/config.toml
systemctl enable --now containerd

# ④ 三件套
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key | \
  gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /" \
  > /etc/apt/sources.list.d/kubernetes.list
apt-get update -qq && apt-get install -y -qq kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl containerd runc
```

## 判官卡：数据盘挂哪里

```
选项 A 挂 /var/lib/longhorn（本次选）
  优点：Longhorn 的默认数据路径，装完不用改 defaultDataPath，节点磁盘自动识别
  缺点：盘和 Longhorn 绑死，将来换存储要重挂

选项 B 挂 /data，再在 Longhorn 里注册
  优点：通用
  缺点：多一步 nodes.longhorn.io 注册 + tag，忘了就出现"节点有盘但调度不上去"

本次：worker 用 A（省事），infra/spare 用 B（它们不跑 Longhorn）
判据：盘只服务一个组件时用它的默认路径；盘要服务多个组件时统一 /data。
```

## 核心大坑（3 条）

```
现象：apt 报 Unable to locate package containerd
根因：26.04 源里包名是 containerd，不是 containerd.io；且要先进 apt-get update
防：按 ③ 的包名写，别从 22.04 的经验里抄 containerd.io

现象：kubelet 起来就 CrashLoop，报 cgroup 相关
根因：containerd 的 SystemdCgroup 还是 false
防：装完立刻 grep 一次，必须为 1

现象：挂盘后重启变成"盘没挂、目录被写满"
根因：只 mount 写了 fstab（或反过来只写了 fstab 没 mount -a 验证）
防：挂完必须 findmnt 看一眼，再 reboot 一台验证
```
