# 11 · 回滚与重装（kubeadm reset 之后必须手工清的残留）

> 用途：这一章只在"要重来一遍"时看。顺序很重要，先拆上层再拆下层，
> 否则会有 Pod 卡在 Terminating、PVC 删不掉、CNI 残留导致新集群 Pod 起不来。

---

## 一、拆除顺序（从上层往下）

```
① GitOps 层     ArgoCD（否则它会不断把被删的东西重建回来）
② 业务与应用     apps 命名空间、Gateway、HTTPRoute
③ 可观测/安全    monitoring、logging、kyverno
④ 存储          Longhorn（先删 PVC/卷，再卸 helm，最后清数据盘）
⑤ 入口          Envoy Gateway、cert-manager
⑥ CNI           Cilium（在 reset 之前卸，残留更少）
⑦ 控制面        三台 kubeadm reset
⑧ 底座          keepalived / haproxy / 主机名 / hosts / sysctl（要重装就保留）
```

每一步的具体命令：

```bash
export KUBECONFIG=/etc/kubernetes/admin.conf

# ① 先关自愈，否则删了还会回来
kubectl -n argocd patch application apps --type merge -p '{"spec":{"syncPolicy":null}}'
helm uninstall argocd -n argocd
helm uninstall gitea -n gitea

# ② 业务
kubectl delete ns apps --wait=true --timeout=300s

# ③ 可观测与安全
helm uninstall kps -n monitoring
helm uninstall loki -n logging
helm uninstall kyverno -n kyverno
kubectl delete ns monitoring logging kyverno kyv-test --ignore-not-found

# ④ 存储（务必先删掉所有 PVC，再卸 Longhorn）
kubectl get pvc -A
kubectl delete pvc --all -n apps -n monitoring -n logging -n gitea 2>/dev/null
kubectl delete ns longhorn-system --wait=true

# ⑤ 入口
helm uninstall eg -n envoy-gateway-system
helm uninstall cert-manager -n cert-manager

# ⑥ CNI
helm uninstall cilium -n kube-system
```

## 二、kubeadm reset 之后必须手工清的残留

`kubeadm reset -f` 只清它自己管的，下面这些**不会**被清掉，留着就会让下一次 init/join 出怪问题：

```bash
# 逐台执行（3 台控制面 + 5 台 worker）

kubeadm reset -f --cri-socket unix:///run/containerd/containerd.sock

# 1) 静态 Pod 清单（reset 偶尔留，留着会自己起旧组件）
rm -rf /etc/kubernetes/manifests/*.yaml

# 2) etcd 数据（不清会导致新集群带着旧成员信息启动失败）
rm -rf /var/lib/etcd

# 3) CNI 配置与状态（★ 最容易漏，漏了新集群 Pod 拿不到 IP）
rm -rf /etc/cni/net.d/* /var/lib/cni /var/run/cilium /var/lib/cilium
ip link delete cilium_host 2>/dev/null
ip link delete cilium_net 2>/dev/null
ip link delete cilium_vxlan 2>/dev/null

# 4) kubelet 配置（reset 会删，明确一下更保险）
rm -f /var/lib/kubelet/config.yaml /var/lib/kubelet/kubeadm-flags.env
rm -rf /var/lib/kubelet/pki

# 5) kubeconfig 与证书
rm -rf /etc/kubernetes
rm -rf /root/.kube

# 6) iptables / nft 残留（Cilium 卸载后可能留下链）
iptables-save | grep -c KUBE           # 理想是只剩 kubelet 那两个链，且此时应为 0
# 需要彻底清就重启一次，最干净：reboot

# 7) 审计与加密目录（下次 init 前要重新放文件）
rm -rf /etc/kubernetes/audit /etc/kubernetes/enc /var/log/kubernetes
```

**验证清干净的判据**：

```bash
ls /etc/kubernetes 2>&1        # No such file or directory
ls /var/lib/etcd 2>&1          # No such file or directory
ip -o link show | grep -c cilium   # 0
systemctl is-active kubelet     # inactive 或 failed（都正常）
```

## 三、入口与云资源

```bash
# keepalived / haproxy（要重装集群就停掉，避免 VIP 抢来抢去）
systemctl disable --now keepalived haproxy

# HAVIP 解绑（不解绑，下次绑会报 status 不对）
aliyun vpc UnassociateHaVip --HaVipId havip-j6crlqrs65eu0p9ulankm \
  --InstanceId i-j6cftz561iu93ytdbcfd
# 三台逐个解绑；若整个环境不用了再 DeleteHaVip
```

**注意**：HAVIP 可以保留复用。本次就是复用了前一天建的 172.23.163.97，省了创建步骤。

## 四、存储数据盘

```bash
# 只在"确认数据不要了"的时候做
for h in 172.23.163.101 172.23.163.105 172.23.163.104 172.23.163.102 172.23.163.103; do
  ssh root@$h 'systemctl stop longhorn* 2>/dev/null; \
               umount /var/lib/longhorn 2>/dev/null; \
               mkfs.ext4 -F -L longhorn /dev/vdb'
  # fstab 里的 UUID 会变，重装后要重新写
done
```

如果只是重装 K8s、想保留长期数据，就别格式化盘，只 umount，重装后再挂回同一路径。

## 五、重装时的三个注意点

```
① 加密 key 要沿用还是重生成
   沿用（推荐）：把同一份 enc-key.b64 再放回 /etc/kubernetes/enc/，旧备份仍可解密
   重生成：之前用旧 key 加密的 etcd 快照，新集群无法直接解密读取

② certSANs 必须重新核对
   重装时 VIP 可能变了（HAVIP 换 IP），kubeadm.yaml 的 certSANs 与
   controlPlaneEndpoint 都要跟着改，否则又会在 join 时撞 x509

③ 上次的 hostname / hosts 不用撤
   同名同 IP 重装最省事；改了名或改了 IP，/etc/hosts 与 certSANs 都要同步
```

## 六、想整套重来一遍的最短路径

```bash
# 0) 记录当前值（IP / VIP / 版本），后面全册都要用
# 1) 按第一节顺序拆到 cilium
# 2) 8 台执行第二节的 reset + 清残留
# 3) 回到 03 章重新跑地基（sysctl/hosts 若没变可跳过）
# 4) 04 章 HAVIP → haproxy → keepalived → 加密/审计文件 → init → join
# 5) 05 章 Cilium（记得 nonMasqueradeCIDRs 一定要按当前 VPC 网段改）
# 6) 06 章 存储（容量账先算，别重犯 219G > 208G）
# 7) 07~08 章 监控与交付
```

预计耗时（本次真实节奏参考）：

```
地基 8 台           约 40 分钟（含两次批量推送与回读）
控制面 HA           约 50 分钟（HAVIP + haproxy + keepalived + init + join + etcd 快照）
网络与入口          约 70 分钟（Cilium + 排 SNAT 事故 + Gateway + TLS + 策略）
存储与灾备          约 60 分钟（含挂盘、Longhorn、备份目标、恢复演练）
可观测与安全        约 60 分钟（含监控栈、Loki、PSA、Kyverno、RBAC）
交付与演练          约 50 分钟（Gitea、ArgoCD、六场演练、巡检）
```
