## 5.1 metrics-server：先让 kubectl top 有数

### 在干什么

装 metrics-server，为 `kubectl top` 和 HPA 提供资源数据。

### 为什么现在做

kube-prometheus-stack **不含** 它。很多人装完 Prometheus 发现 `kubectl top` 报
"Metrics API not available"，就是漏了这一件。

### 敲什么

```bash
helm repo add metrics-server https://kubernetes-sigs.github.io/metrics-server/ \
  && helm repo update metrics-server

helm upgrade --install metrics-server metrics-server/metrics-server -n kube-system \
  --set replicas=2 --set args="{--kubelet-insecure-tls}" --wait --timeout 6m

kubectl top nodes
```

### 看到什么算过（本次真实回显）

```
NAME  CPU(cores) CPU(%) MEMORY(bytes) MEMORY(%)
cp-1  308m        8%     2207Mi        32%
cp-2  238m        6%     1458Mi        21%
cp-3  230m        6%     1506Mi        22%
```

## 5.2 kube-prometheus-stack：2 副本 + 持久化 + PDB

### 在干什么

装 Prometheus / Alertmanager / Grafana / node-exporter / kube-state-metrics，并让关键组件多副本、有持久化、有 PDB。

### 敲什么（values 关键段）

```yaml
grafana:
  replicas: 2
  persistence: {enabled: false}
  topologySpreadConstraints:
    - maxSkew: 1
      topologyKey: kubernetes.io/hostname
      whenUnsatisfiable: ScheduleAnyway
      labelSelector: {matchLabels: {app.kubernetes.io/name: grafana}}

prometheus:
  replicas: 2
  retention: 7d
  retentionSize: "18GB"
  podDisruptionBudget: {enabled: true, minAvailable: 1}
  storageSpec:
    volumeClaimTemplate:
      spec:
        storageClassName: longhorn
        accessModes: ["ReadWriteOnce"]
        resources: {requests: {storage: 20Gi}}

alertmanager:
  replicas: 3
  podDisruptionBudget: {enabled: true, minAvailable: 1}
  storage:
    volumeClaimTemplate:
      spec:
        storageClassName: longhorn
        accessModes: ["ReadWriteOnce"]
        resources: {requests: {storage: 2Gi}}
  config:
    route:
      receiver: default-webhook
      group_by: [alertname, namespace, severity]
      routes:
        - matchers: ['severity="critical"']
          receiver: default-webhook
          continue: true
    receivers:
      - name: default-webhook
        webhook_configs:
          - url: http://alert-sink.monitoring.svc.cluster.local:8080/alerts
            send_resolved: true
```

Grafana 密码走 Secret（两条 key 都要，本次踩过）：

```bash
kubectl -n monitoring create secret generic grafana-admin \
  --from-literal=admin-user=admin \
  --from-literal=admin-password="$(openssl rand -base64 18)"

helm upgrade --install kps prometheus-community/kube-prometheus-stack -n monitoring \
  -f values.yaml --set grafana.admin.existingSecret=grafana-admin \
  --wait --timeout 15m
```

### 看到什么算过

```bash
kubectl -n monitoring get sts -o custom-columns=NAME:.metadata.name,DESIRED:.spec.replicas,READY:.status.readyReplicas
kubectl -n monitoring get pvc
kubectl -n monitoring get pdb
```

```
本次真实结果
alertmanager-...   DESIRED=3 READY=3
prometheus-...     DESIRED=2 READY=2
PVC：alertmanager 2Gi × 3 + prometheus 20Gi × 2，全部 Bound（Longhorn）
PDB：两个都有，minAvailable=1，allowed disruptions 分别是 2 / 1
```

### 本次踩的真坑：helm `--wait` 超时 → 副本数没生效

```
现象：helm install 跑超过 10 分钟被中断，release 停在 pending-install，
      STS 只有 1 副本，values 里的 replicas: 2/3 没体现
根因：单条命令超时被强杀，安装没走完；后续 helm upgrade 又报 "another operation in progress"
解法（本次采用）：不动 helm 状态，直接用 operator 原生对象改
  kubectl -n monitoring patch prometheus <name> --type merge -p '{"spec":{"replicas":2,"retention":"7d",...}}'
  kubectl -n monitoring patch alertmanager <name> --type merge -p '{"spec":{"replicas":3,...}}'
  → 90 秒内 STS 扩到目标副本，PVC 自动创建并 Bound
```

**判官卡**：改副本数，改 STS 还是改 CR？

```
改 STS：会被 operator 立刻回滚，白改
改 CR ：operator 按 CR 重建 STS，这才是正路
```

## 5.3 告警链路：先证明"能送到"，再谈分级

### 在干什么

部署一个 webhook 落点（alert-sink），验证 Alertmanager 真的把告警发出去了。

### 为什么现在做

Alertmanager 默认接收器是 null，所有告警静默丢弃。不验证这一条，"监控"等于装饰。

### 敲什么

```yaml
# alert-sink：一个只记录 POST 的小服务
apiVersion: apps/v1
kind: Deployment
metadata: {name: alert-sink, namespace: monitoring}
spec:
  replicas: 1
  selector: {matchLabels: {app: alert-sink}}
  template:
    metadata: {labels: {app: alert-sink}}
    spec:
      containers:
        - name: sink
          image: docker.io/library/python:3.12-alpine
          command: ["python","-c"]
          args:
            - |
              import http.server, socketserver
              class H(http.server.BaseHTTPRequestHandler):
                  def do_POST(self):
                      n=int(self.headers.get('content-length',0)); b=self.rfile.read(n)
                      open('/tmp/alerts.log','ab').write(b+b'\n')
                      self.send_response(200); self.end_headers(); self.wfile.write(b'ok')
                  def do_GET(self):
                      import os
                      self.send_response(200); self.end_headers()
                      self.wfile.write(open('/tmp/alerts.log','rb').read() if os.path.exists('/tmp/alerts.log') else b'none')
                  def log_message(self,*a): pass
              socketserver.TCPServer(('0.0.0.0',8080),H).serve_forever()
          ports: [{containerPort: 8080}]
---
apiVersion: v1
kind: Service
metadata: {name: alert-sink, namespace: monitoring}
spec:
  selector: {app: alert-sink}
  ports: [{port: 8080, targetPort: 8080}]
```

### 看到什么算过（本次真实回显）

```bash
kubectl -n monitoring exec deploy/alert-sink -- cat /tmp/alerts.log | head -c 400
```

```
{"receiver":"default-webhook","status":"firing","alerts":[{"status":"firing",
 "labels":{"alertname":"Watchdog","prometheus":"monitoring/kps-...","severity":"none"},
 "annotations":{"description":"This is an alert meant to ensure that the entire alerting pipeline is functional...
```

**判据**：看到 `receiver` 名字与 `status":"firing"` 就是链路通。
Watchdog 是 kube-prometheus-stack 自带的心跳告警，能收到它说明整条链路（rule → Alertmanager → receiver）活着。

## 5.6 Kyverno：1.20 只能用 CEL 策略

### 在干什么

三条准入策略：禁 latest tag、强制 requests/limits、禁 privileged。

### 判官卡：用 ClusterPolicy 还是 ValidatingPolicy

```
探针（装完后试建一条老的 ClusterPolicy）
本次真实报错：
  kyverno.io/v1 ClusterPolicy: Kyverno v1.20 removed execution of legacy kyverno.io
  policy types and no longer accepts create or update requests for them

判据
  1.20 起必须用 policies.kyverno.io/v1 的 ValidatingPolicy（CEL 表达式）
```

### 敲什么（三条 CEL 策略）

```yaml
apiVersion: policies.kyverno.io/v1
kind: ValidatingPolicy
metadata: {name: disallow-latest-tag}
spec:
  validationActions: [Deny]
  matchConstraints:
    resourceRules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pods"]
  matchConditions:
    - name: only-apps-namespace
      expression: "object.metadata.?namespace.orValue('') in ['apps','kyv-test']"
  validations:
    - expression: "object.spec.containers.all(c, !c.image.endsWith(':latest'))"
      message: "禁止 latest tag：镜像必须可追溯"
    - expression: "object.spec.containers.all(c, c.image.contains('@sha256:') || c.image.lastIndexOf(':') > c.image.lastIndexOf('/'))"
      message: "镜像必须带显式 tag 或 digest"
---
apiVersion: policies.kyverno.io/v1
kind: ValidatingPolicy
metadata: {name: require-resources}
spec:
  validationActions: [Deny]
  matchConstraints:
    resourceRules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pods"]
  matchConditions:
    - name: only-apps-namespace
      expression: "object.metadata.?namespace.orValue('') in ['apps','kyv-test']"
  validations:
    - expression: >-
        object.spec.containers.all(c,
          has(c.resources) &&
          has(c.resources.requests) && has(c.resources.requests.cpu) && has(c.resources.requests.memory) &&
          has(c.resources.limits) && has(c.resources.limits.cpu) && has(c.resources.limits.memory))
      message: "每个容器必须声明 resources.requests 与 resources.limits"
---
apiVersion: policies.kyverno.io/v1
kind: ValidatingPolicy
metadata: {name: disallow-privileged}
spec:
  validationActions: [Deny]
  matchConstraints:
    resourceRules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pods"]
  matchConditions:
    - name: only-apps-namespace
      expression: "object.metadata.?namespace.orValue('') in ['apps','kyv-test']"
  validations:
    - expression: "object.spec.containers.all(c, !c.securityContext.?privileged.orValue(false))"
      message: "禁止 privileged: true（容器逃逸防线）"
    - expression: "object.spec.containers.all(c, c.securityContext.?allowPrivilegeEscalation.orValue(true) == false)"
      message: "必须显式 allowPrivilegeEscalation: false"
    - expression: "object.spec.containers.all(c, c.securityContext.?capabilities.?drop.orValue([]).exists(d, d == 'ALL'))"
      message: "capabilities.drop 必须包含 ALL"
```

### 看到什么算过（本次真实回显）

```
kubectl get validatingpolicy
  disallow-latest-tag   READY=true
  disallow-privileged   READY=true
  require-resources     READY=true

测试（在 kyv-test，PSA=privileged，避免 PSA 先拦）
latest 镜像       → 禁止 latest tag：镜像必须可追溯
无 resources      → 必须声明 resources.requests 与 resources.limits
privileged: true  → admission webhook "vpol.validate.kyverno.svc-fail-finegrained-disallow-privileged"
                    denied the request: Policy disallow-privileged failed: 禁止 privileged: true
合法 Pod          → 通过（server dry-run 返回对象）
```

## 5.7 RBAC：三个角色

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: {name: platform-view-only}
rules:
  - apiGroups: ["","apps","batch","networking.k8s.io","gateway.networking.k8s.io","storage.k8s.io"]
    resources: ["*"]
    verbs: ["get","list","watch"]
  - apiGroups: ["metrics.k8s.io"]
    resources: ["*"]
    verbs: ["get","list"]

apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: {name: ci-deployer}
rules:
  - apiGroups: ["","apps","batch","networking.k8s.io"]
    resources: ["deployments","statefulsets","daemonsets","replicasets","pods","services",
               "configmaps","secrets","persistentvolumeclaims","networkpolicies","jobs","cronjobs"]
    verbs: ["get","list","watch","create","update","patch","delete"]
  - apiGroups: ["gateway.networking.k8s.io"]
    resources: ["httproutes"]
    verbs: ["get","list","watch","create","update","patch","delete"]
```

## 核心大坑（4 条，每条三行封顶）

```
现象：helm install 监控栈超时，之后 STS 副本数不对、helm 报 another operation in progress
根因：长命令被强杀，release 停在 pending-install
防：改副本数改 CR（Prometheus/Alertmanager 对象），不要直接改 STS；长装包放后台跑

现象：Grafana Pod CreateContainerConfigError
根因：existingSecret 里缺 admin-user 这一条 key
防：Secret 里 admin-user / admin-password 两条都要

现象：Loki 起不来，日志说 compactor.delete-request-store 必须配置
根因：开了 retention 就必须告诉它删除请求存哪
防：compactor.delete_request_store: s3

现象：Kyverno 拒绝创建旧版 ClusterPolicy
根因：1.20 移除 legacy 策略执行
防：改用 policies.kyverno.io/v1 ValidatingPolicy（CEL）
```
