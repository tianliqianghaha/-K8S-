## 3.2 系统基线

### 在干什么

关 swap 与 ufw，统一时区和主机名，写 8 台互解的 hosts，停系统自动更新，并防止 cloud-init 重启后把主机名改回去。

### 为什么现在做

```
swap      kubelet 遇到 swap 直接拒绝启动，K8s 硬要求
ufw       防火墙交给云安全组，两套叠着排障是地狱
时区      etcd 对时钟敏感，偏差 >500ms 会莫名丢 leader
hosts     kubeadm 生成证书要用主机名，certSANs 也依赖它
自动更新  它会在你装包时抢 dpkg 锁，报 "Could not get lock"（本次真撞过）
cloud-init 阿里云镜像托管了主机名，不改配置重启就还原
```

### 在哪台敲

先 cp-1 手敲，再批量推其余 7 台。

### 敲什么（cp-1 手敲版）

```bash

systemctl mask swap.target

# 2) 关 ufw

systemctl enable --now chrony
timedatectl set-ntp true

# 4) 主机名 + hosts（真实地址）
hostnamectl set-hostname cp-1
```

## 3.3 内核基线

### 在干什么

加载三个内核模块，写 sysctl，关闭透明大页（THP）。

### 为什么现在做

```
overlay        容器镜像分层依赖它
br_netfilter   让桥接流量经过 iptables/nftables，Service 转发前提
nf_conntrack   ★ 26.04 上默认不加载，不加载则 nf_conntrack_max 写不进去（静默失效）
ip_forward     容器跨节点通信前提
THP            etcd 对内存分配延迟敏感，THP 会造成周期性抖动
```

**本方案不加载 `ip_vs`**：kube-proxy 被 Cilium 替代，IPVS 在 1.35 已弃用、1.40 默认禁用。装了只会让你以后查 `ipvsadm -Ln` 是空的。

### 在哪台敲

8 台全部，同样先 cp-1 再批量。

### 敲什么

```bash
cat > /etc/modules-load.d/k8s.conf <<'EOF'
overlay
br_netfilter
nf_conntrack
EOF
modprobe overlay
modprobe br_netfilter
modprobe nf_conntrack

cat > /etc/sysctl.d/99-kubernetes.conf <<'EOF'
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
net.netfilter.nf_conntrack_max      = 1048576
fs.inotify.max_user_watches         = 524288
fs.inotify.max_user_instances       = 512
EOF
sysctl --system

cat > /etc/systemd/system/disable-thp.service <<'EOF'
[Unit]
Description=Disable Transparent Huge Pages
After=sysinit.target local-fs.target
Before=kubelet.service

[Service]
Type=oneshot
ExecStart=/bin/sh -c 'echo never > /sys/kernel/mm/transparent_hugepage/enabled'
ExecStart=/bin/sh -c 'echo never > /sys/kernel/mm/transparent_hugepage/defrag'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now disable-thp.service
```

### 看到什么算过（回读 8 台，必须完全相同）

```bash
for h in $NODES; do
  printf "%-16s fwd=%s bnf=%s ct=%s thp=%-8s swap=%s cg=%s\n" "$h" \
    "$(ssh root@$h 'sysctl -n net.ipv4.ip_forward')" \
    "$(ssh root@$h 'sysctl -n net.bridge.bridge-nf-call-iptables')" \
    "$(ssh root@$h 'sysctl -n net.netfilter.nf_conntrack_max')" \
    "$(ssh root@$h 'grep -o "\[never\]" /sys/kernel/mm/transparent_hugepage/enabled || echo NOT-SET')" \
    "$(ssh root@$h 'free -m | awk "/Swap:/{print \$2}"')" \
    "$(ssh root@$h 'stat -fc %T /sys/fs/cgroup')"
done
```

```
本次真实输出（8 行完全相同）
fwd=1 bnf=1 ct=1048576 thp=[never] swap=0 cg=cgroup2fs
```

## 3.4 容器运行时 containerd 2.2.2

### 在干什么

装 containerd 与 runc，配 systemd cgroup 驱动，装 crictl。

### 为什么现在做

```
kubelet 靠 CRI 和运行时说话，containerd 是地基
SystemdCgroup=true 必须与 kubelet 一致，写错则所有 Pod CrashLoop
crictl 后面所有镜像排障都靠它
```

### 判官卡：装哪个 containerd

```
探针（1 分钟）
  apt-cache policy containerd | head -6
  再看 /etc/os-release 的 VERSION_CODENAME

本次判据与实际
  OS = Ubuntu 26.04.1 LTS，codename = resolute
  源里 containerd 候选 = 2.2.2-0ubuntu1.2
  Docker 官方源只到 noble（24.04），resolute 没有 → 教科书那条命令在这里直接 404
  → 判定：用发行版源的 containerd 2.2.2 + runc 1.4.0，不碰 docker 源

为什么可以接受
  K8s 1.37 只要求 containerd ≥ 2.0；2.2.2 满足
  发行版维护，安全更新走 resolute-updates，反而更省心
```

### 在哪台敲

cp-1 手敲看输出，再批量。

### 敲什么

```bash
export DEBIAN_FRONTEND=noninteractive

# 0) 先清抢锁的自动更新，再更新索引（顺序不能反，否则报锁冲突 / 找不到包）
systemctl stop unattended-upgrades apt-daily.service apt-daily-upgrade.service 2>/dev/null || true
pkill -9 unattended-upgr 2>/dev/null || true
sleep 2

# 1) 装（注意：若之前跑过 k8s 脚本把包 hold 了，这里必须先 unhold）
apt-mark unhold containerd runc >/dev/null 2>&1 || true
apt-get -o DPkg::Lock::Timeout=180 update -qq
apt-get -o DPkg::Lock::Timeout=180 install -y -qq containerd runc
apt-mark hold containerd runc >/dev/null

# 2) 生成配置
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml

# 3) ★ 26.04 的配置是 version 3，键名与老教程不同，照抄会改错
#    3.1 cgroup 驱动（位置不变）
sed -i 's/^\(\s*\)SystemdCgroup = false/\1SystemdCgroup = true/' /etc/containerd/config.toml
#    3.2 只改 CRI images.registry 的 config_path（文件里有两处，第二处是 transfer 插件，不能动）
sed -i "0,/^\(\s*\)config_path = ''/s//\1config_path = '\/etc\/containerd\/certs.d'/" /etc/containerd/config.toml
mkdir -p /etc/containerd/certs.d
#    3.3 sandbox 镜像：香港直连 registry.k8s.io，保留默认 pause:3.10.1
#        老教程里的 sandbox_image 键在 2.2.2 里叫 pinned_images.sandbox，不用改就已是可达地址

systemctl daemon-reload
systemctl enable --now containerd
systemctl restart containerd

# 4) crictl
curl -fsSL -o /tmp/crictl.tar.gz \
  https://github.com/kubernetes-sigs/cri-tools/releases/download/v1.37.0/crictl-v1.37.0-linux-amd64.tar.gz
tar -C /usr/local/bin -xzf /tmp/crictl.tar.gz crictl
cat > /etc/crictl.yaml <<'EOF'
runtime-endpoint: unix:///run/containerd/containerd.sock
image-endpoint: unix:///run/containerd/containerd.sock
timeout: 20
debug: false
EOF
```

## 核心大坑（4 条，每条三行封顶）

```
现象：apt 报 Could not get lock /var/lib/dpkg（本次 cp-1 真撞，pid 4010 占锁）
根因：云镜像的 unattended-upgr 在你装包时启动
防：先 systemctl stop + pkill，再用 -o DPkg::Lock::Timeout=180 兜底

现象：apt 报 Unable to locate package containerd（7 台集体失败过一次）
根因：新机器 apt 索引没更新，直接 install 自然找不到
防：install 前一定先 apt-get update；包名是 containerd 不是 containerd.io

现象：apt 报 Held packages were changed and -y was used（同上 7 台）
根因：k8s 脚本先执行了 apt-mark hold containerd runc，而包还没装，后续 install 被拒
防：安装前 apt-mark unhold，装完再 hold（顺序不敏感）

现象：sysctl 写了 nf_conntrack_max 但读不到这个 key
根因：26.04 默认不加载 nf_conntrack，sysctl 静默跳过该行
防：modules-load.d 里加 nf_conntrack 并 modprobe，再 sysctl --system
```
