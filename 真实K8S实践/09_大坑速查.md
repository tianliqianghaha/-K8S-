# 09 · 大坑速查（31 条，按出现顺序排）

> 用法：卡住时按现象找。每条三行封顶：现象 / 根因 / 怎么防。
> 这些全部是 2026-11-20 这次真机部署里真实撞到的，不是推测。

---

## 第 1 章 · 地基阶段

```
① 现象：apt 报 Could not get lock /var/lib/dpkg（本次 pid 4010 占锁）
   根因：云镜像的 unattended-upgr 在你装包时启动
   防：systemctl stop unattended-upgrades apt-daily* + pkill -9 unattended-upgr，
       再统一加 -o DPkg::Lock::Timeout=180

② 现象：apt 报 Unable to locate package containerd（7 台集体失败）
   根因：新机器 apt 索引没更新就 install
   防：install 前先 apt-get update；包名在 26.04 是 containerd，不是 containerd.io

③ 现象：apt 报 Held packages were changed and -y was used
   根因：先跑了 k8s 脚本的 apt-mark hold containerd runc，而包还没装
   防：安装前 apt-mark unhold，装完再 hold（顺序不敏感）

④ 现象：sysctl 里写了 nf_conntrack_max，但 sysctl -n 读不到这个 key
   根因：26.04 默认不加载 nf_conntrack，整行被静默跳过
   防：modules-load.d 加 nf_conntrack 并 modprobe，再 sysctl --system

⑤ 现象：containerd 起来了，但 Pod 全卡在拉 sandbox；config 改了半天没生效
   根因：2.2.2 是 version 3 配置，键名变了（pinned_images.sandbox 取代 sandbox_image），
        config_path 还有两处（CRI images.registry 与 transfer.v1.local）
   防：只改第一处 config_path（0,/pattern/ 限定）；sandbox 用默认的 pause:3.10.1

⑥ 现象：重启后主机名变回 iZxxxxZ
   根因：cloud-init 每次启动按元数据重设主机名
   防：/etc/cloud/cloud.cfg 加 preserve_hostname: true，并把 manage_etc_hosts 设 false
```

## 第 2 章 · 控制面阶段

```
⑦ 现象：探针加完 IP，对端 ping 100% 丢包
   根因：阿里云 VPC 不转发未分配 IP 的 ARP，自建 VIP 在云上天生不可用
   防：先跑探针，不通直接用 HAVIP；本次实测 HAVIP 8/8 节点 0% 丢包

⑧ 现象：init 卡在 wait-control-plane，apiserver 反复 Exit
   根因：scp 加密/审计配置时目标目录还没建，文件没落盘，apiserver 找不到配置
   防：先 mkdir 再 scp，scp 完立刻 ls 确认（本次 cp-1 踩了，cp-2/3 才修好顺序）

⑨ 现象：haproxy 3.2 警告 backend 与 frontend 同名（3.3 起直接报错）
   根因：两段都叫 kube-apiserver
   防：backend 命名 kube_apiserver_back

⑩ 现象：keepalived 一切正常，但 kubectl 全失败
   根因：只 track 网卡，haproxy 挂了 VIP 不漂
   防：vrrp_script 探 127.0.0.1:16443 + weight -30

⑪ 现象：join 报 x509，报错里不提"证书缺 IP"
   根因：certSANs 漏了 VIP
   防：init 时看 [certs] 那行，确认 VIP 在 IP 列表里
```

## 第 3 章 · 网络阶段

```
⑫ 现象：Pod 之间互通，Pod 出网 / 访问 Service / ping 节点全死
   根因：ip-masq-agent 默认把 172.16.0.0/12 当内网不 SNAT，与阿里云节点网段重叠，
        包带着 10.244.x 源 IP 出网，被 VPC 丢弃
   防：nonMasqueradeCIDRs 只留 Pod 段 + Service 段；诊断靠 tcpdump 看源 IP

⑬ 现象：cilium agent CrashLoop，日志找不到 kube-proxy ConfigMap
   根因：--skip-phases=addon/kube-proxy 之后，agent 无从推断 apiserver 地址
   防：显式 --set k8sServiceHost=<VIP> --set k8sServicePort=16443

⑭ 现象：装 Envoy Gateway 报 Installing CRDs with version before v1.5.0 is prohibited
   根因：已装 Gateway API v1.6.1，EG chart 自带 CRD 更旧，被 safe-upgrades 策略拦
   防：--skip-crds 安装；GatewayClass 若没自动建就手建

⑮ 现象：Gateway 一直 PROGRAMMED=False
   根因：云上没有 LB 实现，Service EXTERNAL-IP 永远 pending
   防：不等它；用 NodePort 访问，并从 kubectl get svc 现取端口
       （本次端口从 31320/32663 变成 32691/31559，写死就 Connection refused）
```

## 第 4~6 章 · 存储 / 监控 / 交付阶段

```
⑯ 现象：patch setting backup-target 报 NotFound
   根因：Longhorn 1.13 把备份目标改成 BackupTarget CRD（名字固定 default）
   防：patch spec.backupTargetURL；URL 只写 s3://bucket@region/，
       自定义 endpoint 放 secret 的 AWS_ENDPOINTS（写成三段式会报 invalid input region http:）

⑰ 现象：helm install 监控栈超时；之后副本数不对、helm 报 another operation in progress
   根因：单条命令跑太久被强杀，release 停在 pending-install；直接改 STS 会被 operator 回滚
   防：改副本数改 CR（Prometheus / Alertmanager 对象）；长安装放后台并轮询

⑱ 现象：Kyverno 拒绝创建 ClusterPolicy；日志说 legacy policy types removed
   根因：Kyverno 1.20 只执行 CEL 策略
   防：改用 policies.kyverno.io/v1 ValidatingPolicy；验证时去没打 PSA 的命名空间，
       否则永远是 PSA 先拦，测不到 Kyverno

⑲ 现象：删副本后永远 degraded，报 insufficient storage
   根因：3 副本卷吃满 5×50G 盘，没有单节点空间接新副本
   防：卷总量 × 3 ≤ 可用量 80%；本次 73G 卷 → 219G 物理 vs 208G 可用，必然失败

⑳ 现象：Gitea 一装就拉起 3 个 Postgres + 3 个 Valkey，gitea Pod Init:CrashLoop
   根因：chart 默认 HA 依赖；且默认 Service 是 headless（ClusterIP=None）
   防：关 postgresql-ha/valkey-cluster，DB_TYPE=sqlite3，另补一个普通 ClusterIP Service
```

## 第 7~9 章 · 生产闭环阶段（密钥 / 可观测 / 灾备）

```
㉑ 现象：helm repo add sealed-secrets 失败，或 kubeseal 下载 404
   根因：2026 年仓库从 bitnami-labs 迁到 bitnami
   防：repo 用 https://bitnami.github.io/sealed-secrets；
       kubeseal 用 https://github.com/bitnami/sealed-secrets/releases/download/v0.41.2/...

㉒ 现象：改了 /etc/kubernetes/manifests/etcd.yaml，容器参数还是旧的
   根因：把备份存成 etcd.yaml.bak-metrics 留在同目录，kubelet 把它当成第二个清单解析
   防：备份一律放 /root；改完 touch 清单；还是不动就 stop kubelet + crictl rm + start（一台一台来）

㉓ 现象：patch alertmanager 报 "unknown field spec.config"，配置静默不生效
   根因：promehteus-operator 的 Alertmanager CRD 字段是 spec.configSecret
   防：先建 Secret（key 必须是 alertmanager.yaml），再 patch spec.configSecret 指向它；
       验证要进 pod 看 zcat /etc/alertmanager/config/alertmanager.yaml.gz

㉔ 现象：SealedSecret 一直 UpdateFailed，报 already exists and is not managed by SealedSecret
   根因：目标 Secret 是先手工建的，没有 SealedSecret 的 ownerReference，控制器拒绝接管
   防：删掉手工 Secret 后重启控制器（rollout restart deploy/sealed-secrets-controller）触发全量 reconcile

㉕ 现象：blackbox 探针 probe_success=0，但 curl -k 明明通
   根因：这套环境有三套 CA（集群内部 CA / 集群 CA / Dex 自签 CA），模块用错了
   防：每个探测目标配对应 CA 的模块；三个 CA 放同一个 Secret 挂进 exporter

㉖ 现象：Probe 建好了，Prometheus 里一条数据都没有
   根因：Probe 缺 label release=kps，probeSelector 匹配不到
   防：所有 Probe 都加 labels: {release: kps}；用 /api/v1/targets 看 job 是否出现

㉗ 现象：etcd metrics 端口 2381 本机能通、从节点 IP 不通；Prometheus target DOWN
   根因：kubeadm 默认只听 127.0.0.1
   防：改成 --listen-metrics-urls=http://0.0.0.0:2381（然后按下一条处理重载）

㉘ 现象：Longhorn 卷打了组标签但 RecurringJob 不生效
   根因：kubectl label --all 对 recurring-job-group.longhorn.io/default 这种 key 会静默 "not labeled"
   防：用 kubectl patch --type merge 逐个加 labels；验证时读 json 里的 labels 字段

㉙ 现象：kubectl exec etcd-cp-1 -- sh -c "etcdctl ..." 报 exec: "sh": not found
   根因：etcd 镜像是 distroless，没有 shell
   防：直接 kubectl exec etcd-cp-1 -- etcdctl ...；需要串命令时写进宿主机脚本

㉚ 现象：ctr run -d 起的临时容器"刚起来就没了"
   根因：进程与 SSH 会话同生共死，会话一断就被杀
   防：把「起 → 查 → 停」写进同一条命令；或用 setsid/nohup（本册验证脚本用前者）

㉛ 现象：用 etcdctl get -w json 拿 k8s 对象，python json.loads 报 utf-8 decode error
   根因：k8s 对象在 etcd 里是 protobuf，不是 JSON
   防：验证用"对象数量对比"和"关键词搜索"，不要试图解析 protobuf
```

## 一条横向经验（不属于任何一章，但影响所有长命令）

```
现象：安装类命令跑到一半突然 SIGTERM，日志被截断，release 状态半死不活
根因：单条命令有执行时长上限（本次约 10 分钟），超时被强杀
防：凡是"下载 + helm --wait / 大量镜像"的命令，一律远端 nohup 后台跑 + 轮询日志
```
