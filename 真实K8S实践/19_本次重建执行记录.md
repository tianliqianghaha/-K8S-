## 19.4 今天原样复现的一个坑（值得记：说明昨天那本册子是对的）

```
现象  Pod 之间通，但 Pod→Service / Pod→节点 / Pod→公网 全部超时
根因  ip-masq-agent 默认 nonMasqueradeCIDRs 含 172.16.0.0/12，
      而阿里云节点网段 172.23.x 正好落在里面 → 不发 SNAT，VPC 丢掉 10.244 源地址的包
修法  helm upgrade --reuse-values \
        --set ipMasqAgent.config.nonMasqueradeCIDRs="{10.244.0.0/16,10.96.0.0/12}" \
        --set ipMasqAgent.config.masqLinkLocal=false
回显  {"config":"{\"masqLinkLocal\":false,\"nonMasqueradeCIDRs\":[\"10.244.0.0/16\",\"10.96.0.0/12\"]}"}

★ 附带一条新教训（昨天没写进册子的）
  修好配置后，**修复前创建的 Pod 仍然连不通**（socket/连接状态是旧的）。
  必须删掉重建：kubectl -n verify delete pod -l app=probe
  重建后 6 次请求立刻变成 4:2 正常分摊。
  排查时如果只看"配置已生效"就下结论，会误判成 eBPF LB 坏了。
```

## 19.7 两个必须说清的边界

```
① 控制面仍是单可用区
   3 台控制面都在 cn-hongkong-c（HAVIP 只能挂同一交换机下的实例）。
   含义：c 区整体故障 → etcd 失去仲裁 → 整个集群不可用。
   工作负载层的三 AZ 打散只保证"挂一个 AZ 少 1~2 台 worker 而不丢副本"，
   不保证"挂一个 AZ 集群还活着"。要真正跨 AZ，得把 controlPlaneEndpoint
   从 HAVIP 换成支持跨可用区后端的私网 CLB，并把 3 台控制面拆到 b/c/d。

② 凭据
   AccessKey 已在本轮对话中出现过，建议演练结束后在 RAM 控制台轮换一次；
   实例的 root 口令落在技能目录 state/credentials/（明文），轮换后一并清理。
```
