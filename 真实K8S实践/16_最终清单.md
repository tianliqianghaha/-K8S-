## 16.4 做不了的九项（写清原因与前置条件）

### ① 云 KMS 与 External Secrets Operator

```
为什么做不了
└─ 账号连 OSS 服务都没开通（PUT bucket 返回 UserDisable），KMS 更没开通
   没有 KMS 就没有"根密钥托管"，ESO 也没有可信的 Secret Manager 可读

现在用什么代替
└─ Sealed Secrets + 私钥三处备份（cp-1 / 本机 / infra-01）

要做需要什么
├─ 开通阿里云 KMS，创建 CMK
└─ 创建一个只有 kms:Decrypt 权限的 RAM 子账号
```

### ② 真实告警出口（企业微信 / 钉钉 / 短信 / 电话）

```
为什么做不了
└─ 没有这些平台的组织凭据与机器人 webhook

现在用什么代替
└─ 集群外自建 alert-receiver，/p1 /p2 /p3 三个端点，实测分级投递、抑制、静默

要做需要什么
├─ 一个企微群机器人 webhook（1 分钟就能接上，只改 Alertmanager 的 3 个 url）
└─ 若要电话/短信，还需要云通信服务的模板与签名
```

### ③ 集中式密钥管理（Vault）

```
为什么做不了
└─ 本环境 listener 反复 bind 失败（dev 模式却正常），换端口/网络/监听地址/去 CRLF 全部试过
   判断是该环境下正式模式的 listener 有问题，不再投入

现在用什么代替
└─ Sealed Secrets（静态加密进 Git）
   能力的差距：没有动态租期、没有审计日志、没有自动轮换

要做需要什么
└─ 换成 Vault 官方 Helm chart 装在集群内（而不是 docker compose 跑在宿主），
   或换一台干净机器单独跑 Vault
```

### ④ Harbor 私有镜像仓库

```
为什么做不了
└─ Harbor 全量组件（core/registry/portal/jobservice/trivy/redis/pg）至少需要 30G 可用，
   当前 5 台 worker 的 245G 裸容量已吃掉 213G（3 副本策略下）

现在用什么代替
└─ Gitea 自带容器 registry（支持 push/pull/signature），cosign 验签已验证可用

要做需要什么
└─ 每台 worker 再加一块 100G 数据盘（约 0.1 元/时/块）
```

### ⑤ 多可用区容灾

```
为什么做不了
└─ 8 台机器全部在 cn-hongkong-c 的同一个 VPC 同一可用区
   这不是配置缺失，是资源拓扑缺失：一个 zone 挂了整集群都没

要做需要什么
├─ 至少 2 个可用区、每区 3 台（etcd 奇数成员要求）
└─ HAVIP 也要换成支持跨可用区的 SLB 或 DNS 轮询方案
```

### ⑥ 用 etcd 快照重建一个完整可用集群

```
为什么做不了
└─ 需要一台空机器（或至少一台可以 kubeadm reset 的机器）
   当前 8 台都在承载业务，infra-01 只有 4C8G 且跑着 4 个外部服务

现在做到哪一步
└─ 快照恢复成独立 etcd 实例并读出全部业务对象（18/47/37/146 全一致）
   差的是"把 apiserver/controller/scheduler 指向这个 etcd 起一个可服务的集群"

要做需要什么
└─ 1 台空机器（2C4G 即可），跑：
   kubeadm init --external-etcd-endpoints=http://<恢复实例>:12379 ...
```

### ⑦ OIDC 的 groups claim（按组授权）

```
为什么做不了
└─ Dex 的 password grant 不返回 groups（本地密码连接器的限制）
   已用"按用户绑定 ClusterRoleBinding"绕过（oidc:viewer@k8s.local → platform-view-only）

现在的能力
└─ 身份认证完整、按人授权完整；差别只是"授权粒度是用户不是组"

要做需要什么
└─ 走授权码流程（需要浏览器）：起一个 oauth2-proxy 或 kubelogin，拿 groups claim
   或者接真实 IdP（LDAP/AD/企微），它们的 groups 是标准 claim
```

### ⑧ 分布式追踪（Tempo + OpenTelemetry）

```
为什么做不了
└─ 需要应用侧注入 SDK 或 sidecar 才能产生 span，当前演示业务（podinfo）没有埋点

要做需要什么
└─ 一个会发 OTLP 的应用（或用 OTel Collector 的 eBPF 自动埋点）
```

### ⑨ 成本可视化（Kubecost）

```
为什么做不了
└─ Kubecost 需要云厂商计价 API 的读取权限（RAM 子账号），本账号权限不足

替代
└─ 巡检脚本里已报每个节点的 Longhorn 可用容量，能看出容量瓶颈
```

## 16.5 这套环境现在能回答的问题

```
✅ "集群挂了怎么快速恢复"        Velero RTO 78s / etcd 快照可恢复 / 副本自动重建
✅ "谁能改什么"                  OIDC 身份 + RBAC 三分权 + Kyverno 准入 + 默认拒绝
✅ "密钥怎么管"                  明文不进 Git，SealedSecret + 私钥三处备份
✅ "出问题谁能知道"              7 探针 + SLO 双窗口 + P1/P2/P3 分级投递 + 抑制静默
✅ "怎么保证线上和 Git 一致"      14 个 Application，业务与 addon 都在 Git，自愈实测
✅ "删了东西能不能回来"          删除演练做了五类：Deployment / addon / Secret / SealedSecret / 命名空间

❌ "跨可用区挂了一个 zone 会怎样"  答不了（同 zone）
❌ "密钥泄露了怎么快速轮换"        答不了（无 KMS/Vault 自动轮换）
❌ "值班同事凌晨被叫醒看什么"      答不了（没有真实 IM 出口）
```

## 16.6 如果要继续往前推，顺序建议

```
第一批（最便宜，收益最高）
├─ 接一个企微群机器人 webhook        ← 只改 Alertmanager 三个 url，10 分钟
└─ 每月做一次"生产备份恢复到隔离环境"  ← 需要第二套环境

第二批（补架构缺口）
├─ 每台 worker 加 100G 盘 → 上 Harbor + 提升副本余量
└─ 第二可用区开 3 台 → etcd 跨 AZ + SLB 替代 HAVIP

第三批（补能力）
├─ 开通 KMS → ESO 接管所有 Secret
├─ 空机器一台 → 用 etcd 快照重建完整集群（最硬的那条）
└─ 应用埋点 → Tempo 追踪链路
```
