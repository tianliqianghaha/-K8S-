## 17.4 重建时必须改的硬编码值（本次踩过，提前列清）

```
① 节点 IP 会变
   影响：fleet.py 的 HOSTS 表、HA 的 vrrp_unicast 对端、kubeadm certSAN
   改法：重开机器后先 DescribeInstances 拿新 IP，覆盖 fleet.py，再跑任何脚本

② HAVIP 172.23.163.97 可以复用（未删除），但要重新绑定到新的控制面实例

③ Gateway 的 NodePort 会变（本次 https=32691 / http=31559）
   影响：scripts/s23-probes.yaml 里的 target、文档里的 curl 示例
   改法：kubectl -n envoy-gateway-system get svc 拿实际端口后替换

④ infra-01 的内网 IP 会变（本次 172.23.163.106）
   影响：所有引用它的地方 ——
        CoreDNS hosts（s21）、Alertmanager 三个 webhook url（s27）、
        blackbox 的 dex 目标（s23）、Longhorn/Velero 的 S3 endpoint、
        ArgoCD repo secret、Dex issuer（apiserver 的 --oidc-issuer-url）
   改法：全局 grep 172.23.163.106 全部替换（文档 + scripts + manifests）

⑤ Sealed Secrets 私钥必须沿用本次的备份
   否则 Git 里的 7 个 SealedSecret 全部解不开（它们是绑定这把密钥的）
   做法：新集群装好控制器后，先 apply sealed-secrets-key.backup.yaml，再 rollout restart

⑥ etcd 的 encryption-config 必须沿用或重新生成
   本次的 key 在 k8s-deploy/s2-encryption-config.yaml
   如果换成新 key，旧快照里的 Secret 解不开（15 册验证过快照里是密文）
```

## 17.5 本次验证过、下次可以直接信的经验

```
不需要再试错的部分（文档里有完整回显）
├─ Cilium 在阿里云必须改 ip-masq-agent 的 nonMasqueradeCIDRs（否则 Pod 出网全死）
├─ VIP 必须用 HAVIP，自建 ARP VIP 100% 丢包
├─ Longhorn 1.13 备份目标是 BackupTarget CRD，不是 setting
├─ Kyverno 1.20 只有 CEL 的 ValidatingPolicy，旧 ClusterPolicy 被拒

├─ etcd metrics 默认只听 127.0.0.1，要改 0.0.0.0 才能被 Prometheus 抓到
├─ Alertmanager CR 的字段是 spec.configSecret，不是 spec.config
└─ 备份文件不能留在 staticPodPath 里（会被 kubelet 当第二个清单解析）

需要重新决定的
├─ 是否补第二可用区（本次同 zone，是已知架构缺口）
├─ 是否加盘上 Harbor（本次容量不够）
└─ 是否接真实 IM 告警出口（本次用自建接收端替代）
```
