## AI算力池实践/1.0 说明

把家里一张 RTX 3090 变成云上可调度、可计量、可排队的推理算力池。
云上只放控制面与治理件（4C8G 抢占，约 0.22 元/时），算力在本机。

```
00_总览与复现路线.md      一页看懂：三个实验、架构、复现顺序、版本表、成本
01_第1章_本地GPU节点.md    Windows → WSL2 → 容器内看卡，三道闸门
02_第2章_云端控制面.md     开机器、kubeadm、Cilium、节点 join
03_第3章_实验一.md         云端 gateway + 本地 Agent + WebSocket 反连，四道闸门实测
04_第4章_实验二.md         1卡/2卡、配额、抢占、断网时序、time-slicing 假共享
05_第5章_实验三.md         Kueue 排队、KEDA 弹性、Grafana 大盘、chaos、Argo 回滚、成本
06_经验与陷阱.md           40 条纯文字经验，按层次分组
07_速查卡.md               地址、凭据、自查表、停止与恢复、重建最短路径
scripts/                   5 个源码 + 8 个安装脚本 + README
archive/                   5 份原始过程记录（含失败的探索）
```

实测结论摘要：

```
首字延迟        0.116–0.144 秒（验收线 1.5 秒）
并发拐点        8 与 16 之间，8 并发 P95 仍 0.46 秒
gateway 重启    Agent 1 秒内自动重连
断网 30 秒      3 个积压请求全部成功返回
资源语义        1 卡 Ready / 2 卡 Pending / 配额 Forbidden / 抢占 Preempted
断网时序        50 秒判定 NotReady，恢复后 20 秒回 Ready
Kueue           10 个 Job 只准入 1 个，其余排队后自动交替
chaos 300ms     首字从 0.15 抬到 0.50，撤销后回 0.13
Argo 回滚       坏版本 AnalysisRun 失败 → 自动 abort → 回到上一版
```

一个值得记住的坑：监控默认配置会把低配云盘的 IOPS 打满，
etcd 落盘延迟从毫秒级涨到几十秒，整个控制面假死。
判断依据不是 CPU 和内存（当时 CPU 97% 空闲），而是 etcd 的压缩耗时。
详见 `06_经验与陷阱.md` 第 28 条。

## AI算力网络实践/1.0 说明

把 AI 训练网络的四个目标（无损 / 超低 RTT / 超高带宽 / 低抖动），
在三台普通云服务器上拆成可证伪的实验。不需要 400G 网卡、RDMA 交换机、GPU。

```
00_总览与复现路线.md   一页看懂：四根柱子、复现顺序、成本、边界
01_速查卡.md           地址、五条日常命令、四条实验命令、停止与恢复
README.md              给要动手的人：五分钟上手 + 三个限制
conf/lab.env           唯一要改的文件（角色 + 三个地址）
bin/                   九个脚本：体检/探路/拓扑/故障/观测/验收/QoS/巡检
app/                   三个程序：多路径原型 / 集合通信流量 / MRC 传输
docs/                  01设计 02基础手册 03故障字典 04云上实录 05体系 06进阶 07SOP
nodes/                 三台机器的清单与角色
reports/               真机实测数据（每条带边界）
```

四组实验：

```
① 转发面   SRv6 压缩形态 uSID（RFC 9800）：整条路径编码进 128 bit DA，零扩展头
           证据：c 上同一条流两帧，32 微秒内 DA 从 2:e000 左移成 e000
② 流量形态 ring/tree/a2a/pipe 四种形状 + 大小扫描
           1400 B → 80.1 Mbps / 7153 msg·s⁻¹（延迟敏感）
           60000 B → 681.9 Mbps / 1416 msg·s⁻¹（带宽敏感）
③ 传输策略 MRC/UEC 原型：累积 ACK + SACK 位图 + 立即 NACK + 逐包喷洒
           2% 丢包 → 吞吐塌 25–40 倍（PFC 的存在理由）
           同丢包下 GBN 重传 12.17%、SACK 6.27%（省一半）
           双平面 + SACK 快 55%；双平面 + GBN 反而最差（20.48%）
④ 运维故障 三类故障谱、五步定位法、21 条故障字典、班前五段巡检
```

一个值得记住的坑：云上做端侧源路由不是免费的。
VPC 内不是二层转发（邻居表里对端 MAC 全是 `ee:ff:ff:ff:ff:ff`，虚拟路由器），
必须在 VPC 路由表里为每个 SID 前缀铺静态条目，并关掉 ENI 的源/目的地址检查。
这和 MRC 论文里"交换机装静态表、关掉动态路由"是同一个思路。
详见 `AI算力网络实践/1.0/docs/04-云上部署实录.md` 第 2 节第 4 个坑。

另一条经验：性能实验里"测不出差异"的第一嫌疑永远是测量工具。
本套资料第一版传输原型测出 3.2 Mbps、六种配置差异不到 3%，
换掉 O(n) 找洞和 NACK 风暴之后变成 515 Mbps，差异才显现。
详见 `AI算力网络实践/1.0/docs/03-运维故障字典.md` 第 21 条。
