## AI算力池实践/1.0 说明

把家里一张 RTX 3090 变成云上可调度、可计量、可排队的推理算力池。
云上只放控制面与治理件（4C8G 抢占，约 0.22 元/时），算力在本机。

```
00_总览与复现路线.md      一页看懂：三个实验、架构、复现顺序、版本表、成本
01_第1章_本地GPU节点.md    Windows → WSL2 → 容器内看卡，三道闸门
02_第2章_云端控制面.md     开机器、kubeadm、Cilium、节点 join
03_第3章_实验一.md         云端 gateway + 本地 Agent + WebSocket 反连，四道闸门实测
04_第4章_实验二.md         1卡/2卡、配额、抢占、断网时序、time-slicing 假共享
05_第5章_实验三.md         Kueue 排队、KEDA 弹性、Grafana 大盘、chaos、Argo 回滚、成本
06_经验与陷阱.md           40 条纯文字经验，按层次分组
07_速查卡.md               地址、凭据、自查表、停止与恢复、重建最短路径
scripts/                   5 个源码 + 8 个安装脚本 + README
archive/                   5 份原始过程记录（含失败的探索）
```

实测结论摘要：

```
首字延迟        0.116–0.144 秒（验收线 1.5 秒）
并发拐点        8 与 16 之间，8 并发 P95 仍 0.46 秒
gateway 重启    Agent 1 秒内自动重连
断网 30 秒      3 个积压请求全部成功返回
资源语义        1 卡 Ready / 2 卡 Pending / 配额 Forbidden / 抢占 Preempted
断网时序        50 秒判定 NotReady，恢复后 20 秒回 Ready
Kueue           10 个 Job 只准入 1 个，其余排队后自动交替
chaos 300ms     首字从 0.15 抬到 0.50，撤销后回 0.13
Argo 回滚       坏版本 AnalysisRun 失败 → 自动 abort → 回到上一版
```

一个值得记住的坑：监控默认配置会把低配云盘的 IOPS 打满，
etcd 落盘延迟从毫秒级涨到几十秒，整个控制面假死。
判断依据不是 CPU 和内存（当时 CPU 97% 空闲），而是 etcd 的压缩耗时。
详见 `06_经验与陷阱.md` 第 28 条。
